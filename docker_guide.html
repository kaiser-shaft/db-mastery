01 Старт с нуля за 3 минуты

Если ты никогда раньше не открывал Docker — не переживай. Достаточно запомнить 4 простые аналогии, и всё сразу станет понятным:

🎮 Контейнер

Как игровая приставка в коробке: внутри уже идеально настроен PostgreSQL, MySQL или ClickHouse. Не засоряет твой Windows или macOS.

💾 Том (Volume)

«Флешка с сохранениями». Даже если выключить контейнер, твои таблицы останутся на месте — пока ты сам не сотрёшь их флагом -v.

🪟 Порт

«Окошко выдачи» (5432, 3306, 8080, 8123). Через него браузер, DBeaver и терминал на твоём ПК общаются с базой.

🎛️ Профиль (--profile)

Переключатель модулей. Чтобы не тратить лишнюю память ноутбука, MySQL, реплики и ClickHouse включаются только тогда, когда ты до них дойдёшь.

Четыре шага до первого SQL-запроса

1

Включи Docker Desktop

Установи и запусти Docker Desktop (на Windows/macOS в трее появится значок кита со статусом Engine running). Убедись в терминале, что Docker отвечает:

BASH · Проверка Docker
docker compose version
2

Открой терминал в папке курса

Терминал должен быть открыт в папке, где лежит файл docker-compose.yaml. На Windows удобно нажать ПКМ по папке → Открыть в терминале (или открыть папку в VS Code). Проверка:

BASH / PowerShell · Проверка папки
ls docker-compose.yaml
3

Запусти базовый PostgreSQL 16

В первый раз Docker скачает образ (~1–2 минуты), все следующие запуски занимают 2 секунды:

BASH · Запуск базового контейнера
docker compose up -d
BASH · Проверить, что база «здорова»
docker compose ps

Увидел слово (healthy) напротив course_pg_primary — сервер полностью готов!

4

Войди в базу (и запомни, как выйти!)

Открываем консольный клиент psql внутри контейнера:

BASH · Вход в PostgreSQL
docker exec -it course_pg_primary psql -U student -d learning_db

Появится приглашение learning_db=# — сюда вводятся SQL-запросы из уроков (не забывай ; в конце!). Чтобы выйти обратно в обычный терминал, введи \q и нажми Enter (в MySQL и ClickHouse — exit, универсально — Ctrl+D).

✗ Опасно: стирает все таблицы
docker compose --profile all down -v

Флаг -v (volumes) безвозвратно удаляет «флешки» с данными. Используй только для полного сброса курса с нуля.

✓ Ежедневная пауза: таблицы целы
docker compose --profile all stop

Закончил заниматься — ставь контейнеры на паузу. Они не тратят ОЗУ и батарею, а завтра включатся через up -d со всеми таблицами.

03 Спецкоманды из уроков и правило Docker

Помимо обычного входа в базу, в Модулях 2–3 встречаются три полезные команды: загрузка SQL-файла, перезапуск сервера и имитация сбоя питания. Вот готовые варианты (включая Windows PowerShell):

Урок 2.1 · Загрузка файла миграции (.sql) в PostgreSQL

В Windows PowerShell знак < не работает, поэтому для PowerShell используй вторую команду через Get-Content:

BASH · macOS / Linux
docker exec -i course_pg_primary psql -U student -d learning_db -v ON_ERROR_STOP=1 < migrations/001_add_product_sku.up.sql
PowerShell · Windows
Get-Content migrations/001_add_product_sku.up.sql | docker exec -i course_pg_primary psql -U student -d learning_db -v ON_ERROR_STOP=1
Уроки 3.1 и 3.4 · Перезапуск Shared Buffers и краш-тест WAL (SIGKILL)
BASH · Урок 3.1: перезапуск PostgreSQL (сброс кеша)
docker compose restart pg_primary
BASH · Урок 3.4: 1) имитация отключения питания (SIGKILL)
docker compose kill -s SIGKILL pg_primary
BASH · Урок 3.4: 2) включить обратно и прочитать логи WAL
docker compose up -d pg_primary && docker logs --tail=20 course_pg_primary
Почему где-то docker compose, а где-то docker exec?
1) Включить / выключить / перезапустить стенд → docker compose ... (запускать в папке с docker-compose.yaml; для Модулей 4–6 добавлять --profile).
2) Зайти в базу или посмотреть логи → docker exec -it course_... и docker logs course_... — используют имя контейнера, поэтому работают из любой папки и без --profile!

✗ Ошибка в Adminer и ClickHouse

Писать localhost в поле «Сервер» Adminer или внутри postgresql('localhost:5432', ...) в ClickHouse.

Внутри контейнера localhost указывает на сам этот контейнер, а не на PostgreSQL → будет Connection refused.

Бэкапы, PITR (Урок 5.4), сброс реплики (Урок 5.3) и логи

Логический бэкап через pg_dump и восстановление (Урок 5.4)

Папка ./backups на компьютере примонтирована в /backups внутри course_pg_primary — все дампы появятся прямо в папке проекта.

BASH · Создать сжатый дамп всей базы
docker exec course_pg_primary pg_dump -U student -d learning_db -F c -f /backups/learning_db.dump
BASH · Создать тестовую БД для восстановления
docker exec course_pg_primary createdb -U student learning_db_restore
BASH · Восстановить дамп в learning_db_restore
docker exec course_pg_primary pg_restore -U student -d learning_db_restore /backups/learning_db.dump
Включение PITR / архивирования WAL (Урок 5.4)

1) Открой docker-compose.yaml и в сервисе pg_primary (строки 34–37) убери # в начале 4 строк:

YAML · Фрагмент docker-compose.yaml (сервис pg_primary)
      - -c
      - archive_mode=on
      - -c
      - archive_command=mkdir -p /backups/wal && test ! -f /backups/wal/%f && cp %p /backups/wal/%f

2) Сохрани файл, пересоздай контейнер (данные сохранятся!) и проверь статус архиватора:

BASH · Применить настройку PITR
docker compose up -d pg_primary
BASH · Проверить, что archive_mode = on
docker exec course_pg_primary psql -U student -d learning_db -c "SHOW archive_mode;"
Сброс реплики pg_standby после Failover (Урок 5.3)

Если ты перевёл course_pg_standby в режим записи (SELECT pg_promote();), удали только её контейнер и её том — при запуске она сама склонируется заново с Primary:

07 Если что-то пошло не так (частые ошибки новичков)

Кликни на сообщение об ошибке из терминала — внутри готовое решение за 10 секунд:

Cannot connect to the Docker daemon / error during connect

Причина: Docker Desktop не запущен или ещё загружается.

Решение: Запусти приложение Docker Desktop, дождись зелёного статуса Engine running (15–30 секунд) и повтори команду. На Linux: sudo systemctl start docker.

no configuration file provided: not found

Причина: Терминал открыт не в той папке, где лежит docker-compose.yaml.

Решение: Перейди в папку курса (cd путь/к/папке) или открой её в VS Code и запусти встроенный терминал. Проверь командой ls docker-compose.yaml.

role "postgres" does not exist или password authentication failed

Причина: По привычке указан логин postgres или неверный пароль.

Решение: В нашем docker-compose.yaml везде используется логин student и пароль student_pass (root в MySQL — root_pass):

BASH · Правильный вход
docker exec -it course_pg_primary psql -U student -d learning_db
no such service: mysql_innodb / pg_standby / clickhouse

Причина: Эти сервисы включены только внутри своих профилей (mod4, mod5, mod6). Команды docker compose exec/logs/rm без флага --profile их не видят.

Решение: Для входа и логов используй docker exec -it course_... и docker logs course_... (как в этом гиде) — им --profile не нужен. Для запуска/остановки всегда указывай профиль: docker compose --profile mod5 up -d.

Bind for 0.0.0.0:5432 failed: port is already allocated (порт занят)

Причина: На твоём компьютере уже работает локальный PostgreSQL (или MySQL на 3306) и занял этот порт.

Решение: Открой docker-compose.yaml, найди в нужном сервисе секцию ports: и поменяй левое число (порт на ПК), например: "5432:5432" → "55432:5432" (правое число не трогай!), затем выполни docker compose up -d. Команда docker exec продолжит работать как раньше, а в DBeaver укажи новый порт 55432.

Error response from daemon: container course_... is not running (или No such container)

Причина: Контейнер ещё не запущен, стоит на паузе после stop или не включён нужный профиль.

Решение: Подними нужный профиль (например, docker compose up -d для PostgreSQL или docker compose --profile mod6 up -d для ClickHouse) и подожди 5–10 секунд.

Я «застрял» в терминале: вижу learning_db=# или learning_db-#

Причина: Ты находишься внутри psql, а не в обычном терминале. Значок -# (минус вместо равно) означает, что ты начал SQL-команду и забыл поставить в конце ;.

Решение: Введи ; и нажми Enter (или Ctrl+C для сброса строки). Чтобы полностью выйти из базы в обычный терминал, введи \q и нажми Enter.

Adminer или ClickHouse выдаёт Connection refused при подключении к localhost:5432

Причина: Внутри Docker слово localhost для каждого контейнера означает самого себя.

Решение: В Adminer (поле «Сервер»), в функции postgresql(...) ClickHouse и в CREATE SUBSCRIPTION всегда пиши имя сервиса: pg_primary (или mysql_innodb, pg_standby), а не localhost.

На Windows в Git Bash команда docker exec -it пишет ошибку про TTY

Причина: Старый Git Bash (MinGW) некорректно передаёт интерактивный ввод в Docker.

Решение: Используй стандартный Windows Terminal / PowerShell (или встроенный терминал VS Code) — там docker exec -it работает сразу. Альтернатива в Git Bash: добавь winpty в начале (winpty docker exec -it ...).

Главное правило работы со стендом Пришёл учиться → docker compose up -d (или нужный --profile) → вошёл через docker exec -it course_... (или открыл Adminer / ClickHouse Play) → закончил учиться → docker compose --profile all stop. Все твои таблицы останутся в полной сохранности до следующего урока!
