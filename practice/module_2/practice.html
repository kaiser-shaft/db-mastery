2.1.2 Соединяем покупателей с их городами
Очень легко

Соедини таблицы customers (c) и cities (ci) через INNER JOIN по c.city_id = ci.id. Выведи c.id, c.full_name, ci.name AS city, ci.timezone. Отсортируй по c.id.

Подсказка: обрати внимание, что Данияр (id = 5) с city_id IS NULL не попадёт в INNER JOIN — в Уроке 2.2 мы исправим это с помощью LEFT JOIN.

Показать ответ
SQL
SELECT
    c.id,
    c.full_name,
    ci.name AS city,
    ci.timezone
FROM customers AS c
INNER JOIN cities AS ci
    ON ci.id = c.city_id
ORDER BY c.id;
2.1.3 Собираем чек заказа № 1 через таблицу-мостик
Очень легко

Соедини order_items (oi) и products (p) для заказа oi.order_id = 1. Выведи p.title, oi.quantity, oi.unit_price и сумму позиции oi.quantity * oi.unit_price AS line_total. Отсортируй по p.id.

Показать ответ
SQL
SELECT
    p.title,
    oi.quantity,
    oi.unit_price,
    oi.quantity * oi.unit_price AS line_total
FROM order_items AS oi
INNER JOIN products AS p
    ON p.id = oi.product_id
WHERE oi.order_id = 1
ORDER BY p.id;

Часть Б. Связи 1:1 и «многие-ко-многим» (M:N), приведение к 1НФ

2.1.4 Профиль покупателя: реализуем связь 1:1 и ловим дубликат
Базовое

Создай таблицу-спутник customer_profiles со связью 1:1 к customers через общий первичный ключ: customer_id INT PRIMARY KEY REFERENCES customers(id) ON DELETE CASCADE, telegram TEXT UNIQUE, birth_date DATE. Добавь профили для клиентов 1 ('@alisa_k', '2004-03-15') и 2 ('@boris_t', '2002-11-20'). Выведи всех клиентов с их профилями через LEFT JOIN, а затем попробуй вставить второй профиль для клиента 1 — убедись, что база заблокирует дубликат.

Подсказка: когда customer_id одновременно является и PRIMARY KEY, и FOREIGN KEY, у каждого клиента может быть ровно 0 или 1 профиль.

Показать ответ
SQL
DROP TABLE IF EXISTS customer_profiles;

CREATE TABLE customer_profiles (
    customer_id INT PRIMARY KEY REFERENCES customers(id) ON DELETE CASCADE,
    telegram    TEXT UNIQUE,
    birth_date  DATE
);

INSERT INTO customer_profiles (customer_id, telegram, birth_date) VALUES
    (1, '@alisa_k', '2004-03-15'),
    (2, '@boris_t', '2002-11-20');

SELECT c.id, c.full_name, cp.telegram, cp.birth_date
FROM customers AS c
LEFT JOIN customer_profiles AS cp
    ON cp.customer_id = c.id
ORDER BY c.id;

-- Краш-тест связи 1:1 — упадёт с ошибкой duplicate key (customer_profiles_pkey):
INSERT INTO customer_profiles (customer_id, telegram, birth_date)
VALUES (1, '@alisa_second', '2004-03-15');

У остальных клиентов в результате LEFT JOIN профиль равен NULL — это типичная опциональная связь 1 : 0..1.

2.1.5 Создаём справочник тегов и таблицу-мостик
Базовое

Создай две таблицы: 1) tags (id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY, name TEXT NOT NULL UNIQUE); 2) таблицу-мостик product_tags с колонками product_id (ссылка на products(id) ON DELETE CASCADE), tag_id (ссылка на tags(id) ON DELETE CASCADE) и составным PRIMARY KEY (product_id, tag_id). Добавь 3 тега ('хит', 'подарок', 'зима') и привяжи: к товару 1 — тег 1, к товару 4 — теги 1 и 3, к товару 7 — теги 1 и 2.

Показать ответ
SQL
DROP TABLE IF EXISTS product_tags, tags CASCADE;

CREATE TABLE tags (
    id   INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL UNIQUE
);

CREATE TABLE product_tags (
    product_id INT NOT NULL REFERENCES products(id) ON DELETE CASCADE,
    tag_id     INT NOT NULL REFERENCES tags(id)     ON DELETE CASCADE,
    PRIMARY KEY (product_id, tag_id)
);

INSERT INTO tags (name) VALUES
    ('хит'),     -- id = 1
    ('подарок'), -- id = 2
    ('зима');    -- id = 3

INSERT INTO product_tags (product_id, tag_id) VALUES
    (1, 1),
    (4, 1), (4, 3),
    (7, 1), (7, 2);
2.1.6 Читаем товары с их тегами через мостик
Базовое

Выведи названия товаров и привязанные к ним теги из таблиц products (p), product_tags (pt) и tags (t): колонки p.title и t.name AS tag_name. Отсортируй по p.id, t.name.

Показать ответ
SQL
SELECT
    p.title,
    t.name AS tag_name
FROM products AS p
INNER JOIN product_tags AS pt
    ON pt.product_id = p.id
INNER JOIN tags AS t
    ON t.id = pt.tag_id
ORDER BY p.id, t.name;
2.1.7 Эксперимент: проверяем защиту составного ключа и FK
Эксперимент

Попробуй выполнить два «ломающих» INSERT в таблицу product_tags: 1) повесь тег 1 на товар 1 повторно ((1, 1)); 2) привяжи несуществующий тег 999 к товару 1 ((1, 999)). Посмотри на сообщения об ошибках PostgreSQL.

Показать ответ
SQL
-- 1. Ошибка дубликата составного PRIMARY KEY (product_tags_pkey):
INSERT INTO product_tags (product_id, tag_id) VALUES (1, 1);

-- 2. Ошибка внешнего ключа (product_tags_tag_id_fkey):
INSERT INTO product_tags (product_id, tag_id) VALUES (1, 999);

Обе попытки будут заблокированы самой СУБД: составной ключ запрещает дубли, а FOREIGN KEY — ссылки на несуществующие теги.

2.1.8 Разбираем список через запятую в 1НФ
Среднее

Создай «грязную» таблицу bad_orders_sheet (order_id INT, customer_name TEXT, items_list TEXT), вставь 2 строки: (101, 'Алиса Ким', 'Худи, Стикерпак') и (102, 'Тимур Касымов', 'Клавиатура, Мышь, Коврик'). Затем напиши SELECT, который развернёт items_list в 1НФ (1 товар = 1 строка) с колонками order_id, customer_name и item_name.

Подсказка: используй связку TRIM(unnest(string_to_array(items_list, ','))) AS item_name.

Показать ответ
SQL
DROP TABLE IF EXISTS bad_orders_sheet;

CREATE TABLE bad_orders_sheet (
    order_id      INT,
    customer_name TEXT,
    items_list    TEXT
);

INSERT INTO bad_orders_sheet VALUES

Часть В. Безопасные миграции схемы БД (UP и DOWN)

2.1.9 Безопасная UP-миграция: добавляем NOT NULL колонку sku
Среднее

Создай журнал версий schema_migrations (version TEXT PRIMARY KEY, applied_at TIMESTAMPTZ NOT NULL DEFAULT now()). Затем внутри транзакции BEGIN; ... COMMIT; добавь в непустую таблицу products колонку sku TEXT, заполни старые строки (backfill) значениями 'SKU-' || LPAD(id::TEXT, 4, '0'), включи SET NOT NULL и ограничение products_sku_unique UNIQUE (sku), а в конце запиши '001_add_product_sku' в schema_migrations.

Подсказка: в непустую таблицу нельзя сразу добавить NOT NULL без значения по умолчанию — действуй в 3 шага: ADD COLUMN → UPDATE → SET NOT NULL.

Показать ответ
SQL
CREATE TABLE IF NOT EXISTS schema_migrations (
    version    TEXT PRIMARY KEY,
    applied_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

BEGIN;

ALTER TABLE products
    ADD COLUMN sku TEXT;

UPDATE products
SET sku = 'SKU-' || LPAD(id::TEXT, 4, '0')
WHERE sku IS NULL;

ALTER TABLE products
    ALTER COLUMN sku SET NOT NULL,
    ADD CONSTRAINT products_sku_unique UNIQUE (sku);

INSERT INTO schema_migrations (version)
VALUES ('001_add_product_sku');

COMMIT;

SELECT id, title, sku FROM products ORDER BY id;
2.1.10 Откат схемы (DOWN-миграция 001)
Среднее

Напиши парную DOWN-миграцию внутри транзакции BEGIN; ... COMMIT;: удали ограничение products_sku_unique и колонку sku из products (используй IF EXISTS), а затем убери запись '001_add_product_sku' из schema_migrations.

Показать ответ
SQL
BEGIN;

ALTER TABLE products
    DROP CONSTRAINT IF EXISTS products_sku_unique,
    DROP COLUMN IF EXISTS sku;

DELETE FROM schema_migrations
WHERE version = '001_add_product_sku';

COMMIT;

SELECT * FROM schema_migrations;

В PostgreSQL DDL-команды (ALTER TABLE, CREATE TABLE) работают внутри транзакции: при любой ошибке схема откатится целиком.

2.2.4 Ловушка LEFT JOIN: фильтр в ON против WHERE
Базовое

Выведи всех 7 клиентов (c.id, c.full_name) и номера только их оплаченных заказов (o.id AS paid_order_id, o.status). Клиенты без оплаченных заказов (Данияр и Ольга) обязательно должны остаться в списке с NULL. Отсортируй по c.id, o.id.

Подсказка: условие o.status = 'paid' нужно ставить в ON, а не в WHERE!

Показать ответ
SQL
SELECT
    c.id,
    c.full_name,
    o.id AS paid_order_id,
    o.status
FROM customers AS c
LEFT JOIN orders AS o
    ON o.customer_id = c.id
   AND o.status = 'paid'
ORDER BY c.id, o.id;

Часть Б. UNION / UNION ALL и условная логика CASE WHEN

2.2.5 Единая база контактов без дублей (UNION)
Очень легко

Склей вертикально списки full_name, email из таблиц customers и newsletter_leads так, чтобы дубликаты (Мария и Тимур) автоматически удалились. Отсортируй результат по email.

Показать ответ
SQL

FROM customers

UNION

FROM newsletter_leads

2.3.8 Двухшаговый CTE: клиенты с тратами выше среднего
Среднее

Шаг 1 (CTE customer_totals): посчитай clean_name и общую сумму оплаченных покупок (total_spent) по каждому платящему клиенту. Шаг 2 (CTE store_avg): вычисли среднее ROUND(AVG(total_spent), 2) AS avg_spent. В финальном SELECT выведи тех, у кого total_spent > avg_spent, вместе с колонкой отрыва total_spent - avg_spent AS above_avg.

Показать ответ
SQL
WITH customer_totals AS (
    SELECT
        c.id                             AS customer_id,
        INITCAP(TRIM(c.full_name))       AS clean_name,
        SUM(oi.quantity * oi.unit_price) AS total_spent
    FROM customers AS c
    INNER JOIN orders AS o
        ON o.customer_id = c.id
    INNER JOIN order_items AS oi
        ON oi.order_id = o.id
    WHERE o.status = 'paid'
    GROUP BY c.id, c.full_name
),
store_avg AS (
    SELECT ROUND(AVG(total_spent), 2) AS avg_spent
    FROM customer_totals
)
SELECT
    ct.clean_name,
    ct.total_spent,
    sa.avg_spent,
    ct.total_spent - sa.avg_spent AS above_avg
FROM customer_totals AS ct
CROSS JOIN store_avg AS sa
WHERE ct.total_spent > sa.avg_spent
ORDER BY ct.total_spent DESC;

Средние траты среди 5 платящих клиентов — 46400.00. Выше среднего: Алексей (76 000), Тимур (57 000) и Мария (54 000).

Часть В. Смещение (LAG / LEAD) и скользящие рамки (ROWS BETWEEN)

2.4.7 Динамика выручки по месяцам (MoM через LAG)
Базовое

В CTE monthly_sales посчитай оплаченную выручку по месяцам (sales_month, revenue). Во внешнем запросе с помощью LAG(revenue) добавь выручку прошлого месяца (prev_revenue), разницу (diff_amount) и процент изменения с округлением до 1 знака (growth_pct). Отсортируй по sales_month.

Показать ответ
SQL
WITH monthly_sales AS (
    SELECT
        DATE_TRUNC('month', o.created_at)::date AS sales_month,
        SUM(oi.quantity * oi.unit_price)        AS revenue
    FROM orders AS o
    INNER JOIN order_items AS oi
        ON oi.order_id = o.id
    WHERE o.status = 'paid'
    GROUP BY sales_month
)
SELECT
    sales_month,
    revenue,
    LAG(revenue) OVER w                                              AS prev_revenue,
    revenue - LAG(revenue) OVER w                                    AS diff_amount,
    ROUND((revenue - LAG(revenue) OVER w) * 100.0 / LAG(revenue) OVER w, 1) AS growth_pct
FROM monthly_sales
WINDOW w AS (ORDER BY sales_month)
ORDER BY sales_month;

2.4.8 Сколько дней проходит между покупками клиента?
Среднее

Для каждого оплаченного заказа выведи очищенное имя клиента (clean_name), o.id AS order_id, дату заказа (order_date), дату предыдущего оплаченного заказа этого же клиента (prev_order_date) и разницу в днях (days_between). Отсортируй по c.id, o.created_at, o.id.

Подсказка: в PostgreSQL вычитание двух дат (date - date) сразу возвращает целое число дней.

Показать ответ
SQL
SELECT
    INITCAP(TRIM(c.full_name))                       AS clean_name,
    o.id                                             AS order_id,
    o.created_at::date                               AS order_date,
    LAG(o.created_at::date) OVER w                   AS prev_order_date,
    o.created_at::date - LAG(o.created_at::date) OVER w AS days_between
FROM orders AS o
INNER JOIN customers AS c
    ON c.id = o.customer_id
WHERE o.status = 'paid'
WINDOW w AS (PARTITION BY o.customer_id ORDER BY o.created_at, o.id)
ORDER BY c.id, o.created_at, o.id;
2.4.9 Накопительная выручка и скользящее среднее за 3 заказа
Среднее

В CTE order_totals собери все оплаченные заказы (order_id, order_date, order_total). Во внешнем запросе посчитай накопительный итог (running_total с явным ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) и скользящее среднее за последние 3 заказа с округлением до 2 знаков (moving_avg_3 с ROWS BETWEEN 2 PRECEDING AND CURRENT ROW). Отсортируй по order_date, order_id.

Подсказка: обрати внимание на заказы № 8 и № 9 от 2026-03-20 — благодаря ROWS и order_id в ORDER BY они накапливаются по очереди, без скачка RANGE!

Показать ответ
SQL
WITH order_totals AS (
    SELECT
        o.id                             AS order_id,
        o.created_at::date               AS order_date,
        SUM(oi.quantity * oi.unit_price) AS order_total
    FROM orders AS o
    INNER JOIN order_items AS oi
        ON oi.order_id = o.id
    WHERE o.status = 'paid'
    GROUP BY o.id, o.created_at
)
SELECT
    order_id,
    order_date,
    order_total,
    SUM(order_total) OVER (
        ORDER BY order_date, order_id
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS running_total,
    ROUND(
        AVG(order_total) OVER (
            ORDER BY order_date, order_id
            ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
        ),
        2
    ) AS moving_avg_3
FROM order_totals
ORDER BY order_date, order_id;
2.4.10 Дата следующей покупки (LEAD) и вклад заказа в траты клиента
Среднее

На основе оплаченных заказов (через CTE order_totals) выведи для каждого заказа: clean_name, order_date, order_total, дату следующего заказа того же клиента (next_order_date через LEAD) и долю этого заказа в процентах от всех оплаченных трат данного клиента (pct_of_client_total, округлить до 1 знака). Отсортируй по customer_id, order_date, order_id.

Показать ответ
SQL
WITH order_totals AS (
    SELECT
        o.customer_id,
        INITCAP(TRIM(c.full_name))       AS clean_name,
        o.id                             AS order_id,
        o.created_at::date               AS order_date,
        SUM(oi.quantity * oi.unit_price) AS order_total
    FROM orders AS o
    INNER JOIN customers AS c
        ON c.id = o.customer_id
    INNER JOIN order_items AS oi
        ON oi.order_id = o.id
    WHERE o.status = 'paid'
    GROUP BY o.customer_id, c.full_name, o.id, o.created_at
)
SELECT
    clean_name,
    order_date,
    order_total,
    LEAD(order_date) OVER (
        PARTITION BY customer_id
        ORDER BY order_date, order_id
    ) AS next_order_date,
    ROUND(
        order_total * 100.0
        / SUM(order_total) OVER (PARTITION BY customer_id),
        1
    ) AS pct_of_client_total
FROM order_totals
ORDER BY customer_id, order_date, order_id;

2.5.1 Полная витрина лояльности клиентов
Базовое

Выведи всех 7 клиентов: очищенное имя (customer_name), название города (city, если NULL — 'Не указан'), число оплаченных заказов (paid_orders), сумму оплаченных покупок (total_spent, если нет — 0.00) и сегмент (segment): >= 50000 → 'VIP', > 0 → 'Активный', иначе 'Спящий'. Отсортируй по total_spent DESC, c.id.

Подсказка: соединяй customers с cities, orders (с AND o.status = 'paid' в ON) и order_items через LEFT JOIN.

Показать ответ
SQL
SELECT
    INITCAP(TRIM(c.full_name))                       AS customer_name,
    COALESCE(ci.name, 'Не указан')                   AS city,
    COUNT(DISTINCT o.id)                             AS paid_orders,
    COALESCE(SUM(oi.quantity * oi.unit_price), 0.00) AS total_spent,
    CASE
        WHEN COALESCE(SUM(oi.quantity * oi.unit_price), 0.00) >= 50000 THEN 'VIP'
        WHEN COALESCE(SUM(oi.quantity * oi.unit_price), 0.00) > 0      THEN 'Активный'
        ELSE 'Спящий'
    END AS segment
FROM customers AS c
LEFT JOIN cities AS ci
    ON ci.id = c.city_id
LEFT JOIN orders AS o
    ON o.customer_id = c.id
   AND o.status = 'paid'
LEFT JOIN order_items AS oi
    ON oi.order_id = o.id
GROUP BY c.id, c.full_name, ci.name
ORDER BY total_spent DESC, c.id;

2.5.3 Товары со слабым спросом (0 или 1 продажа)
Среднее

Посчитай по каждому товару из products количество проданных штук в оплаченных заказах (units_sold, 0 если не продавались) и выручку (revenue). Оставь только товары, которых продано не больше 1 штуки (включая 0!). Выведи p.title, p.category, units_sold, revenue. Отсортируй по units_sold ASC, p.id.

Подсказка: используй условную сумму SUM(CASE WHEN o.status = 'paid' THEN oi.quantity ELSE 0 END) после LEFT JOIN, чтобы отменённые и ожидающие заказы не искажали подсчёт и не удаляли товар.

Показать ответ
SQL
SELECT
    p.title,
    p.category,
    SUM(CASE WHEN o.status = 'paid' THEN oi.quantity ELSE 0 END)                  AS units_sold,
    SUM(CASE WHEN o.status = 'paid' THEN oi.quantity * oi.unit_price ELSE 0.00 END) AS revenue
FROM products AS p
LEFT JOIN order_items AS oi
    ON oi.product_id = p.id
LEFT JOIN orders AS o
    ON o.id = oi.order_id
GROUP BY p.id, p.title, p.category
HAVING SUM(CASE WHEN o.status = 'paid' THEN oi.quantity ELSE 0 END) <= 1
ORDER BY units_sold ASC, p.id;

2.5.4 Эффективность курьерских служб из JSONB
Среднее

Сравни службы доставки по оплаченным заказам: выведи courier (из delivery_info ->> 'courier'), число заказов (orders_cnt), число экспресс-заказов (express_orders_cnt), общую выручку (total_revenue) и средний чек заказа с округлением до 2 знаков (avg_order_total). Отсортируй по total_revenue DESC.

Подсказка: сначала посчитай сумму каждого заказа в CTE, иначе AVG усреднит отдельные товарные позиции вместо целых заказов!

Показать ответ
SQL
WITH order_totals AS (
    SELECT
        o.id                                                AS order_id,
        o.delivery_info ->> 'courier'                       AS courier,
        (o.delivery_info @> '{"express": true}'::jsonb)     AS is_express,
        SUM(oi.quantity * oi.unit_price)                    AS order_total
    FROM orders AS o
    INNER JOIN order_items AS oi
        ON oi.order_id = o.id
    WHERE o.status = 'paid'
    GROUP BY o.id, o.delivery_info
)
SELECT
    courier,
    COUNT(*)                                  AS orders_cnt,
    COUNT(*) FILTER (WHERE is_express)        AS express_orders_cnt,
    SUM(order_total)                          AS total_revenue,
    ROUND(AVG(order_total), 2)                AS avg_order_total
FROM order_totals
GROUP BY courier
ORDER BY total_revenue DESC;
2.5.5 Финансовый дашборд: выручка, экспресс-доля, LAG и накопление
Среднее

Собери помесячный отчёт по оплаченным заказам: sales_month, общую выручку (revenue), выручку экспресс-заказов (express_revenue через FILTER и @> '{"express": true}'::jsonb), разницу с прошлым месяцем (diff_prev_month через LAG) и накопительную выручку с начала года (running_total с явным ROWS BETWEEN). Отсортируй по sales_month.

Показать ответ
SQL
WITH monthly AS (
    SELECT
        DATE_TRUNC('month', o.created_at)::date AS sales_month,
        SUM(oi.quantity * oi.unit_price)        AS revenue,
        COALESCE(
            SUM(oi.quantity * oi.unit_price)
                FILTER (WHERE o.delivery_info @> '{"express": true}'::jsonb),
            0.00
        ) AS express_revenue
    FROM orders AS o
    INNER JOIN order_items AS oi
        ON oi.order_id = o.id
    WHERE o.status = 'paid'
    GROUP BY sales_month
)
SELECT
    sales_month,
    revenue,
    express_revenue,
    revenue - LAG(revenue) OVER (ORDER BY sales_month) AS diff_prev_month,
    SUM(revenue) OVER (
        ORDER BY sales_month
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS running_total
FROM monthly
ORDER BY sales_month;
2.5.6 Лидер продаж в каждой категории + доля в кассе и флаг hit
Финал модуля

Среди всех оплаченных заказов найди самый прибыльный товар в каждой категории. Выведи: category, title, булев флаг наличия тега "hit" в specs (is_hit), выручку товара (product_revenue) и его долю в процентах от всей оплаченной выручки магазина (store_share_pct, округлить до 1 знака). Отсортируй по product_revenue DESC.

Подсказка: шаг 1 (CTE product_sales) — выручка по товарам; шаг 2 (CTE ranked) — доля через SUM(product_revenue) OVER () и ROW_NUMBER() OVER (PARTITION BY category ORDER BY product_revenue DESC, id); финал — WHERE pos = 1.

Показать ответ
SQL
WITH product_sales AS (
    SELECT
        p.id,
        p.category,
        p.title,
        (p.specs @> '{"tags": ["hit"]}'::jsonb) AS is_hit,
        SUM(oi.quantity * oi.unit_price)        AS product_revenue
    FROM products AS p
    INNER JOIN order_items AS oi
        ON oi.product_id = p.id
    INNER JOIN orders AS o
        ON o.id = oi.order_id
    WHERE o.status = 'paid'
    GROUP BY p.id, p.category, p.title, p.specs
),
ranked AS (
    SELECT
        *,
        ROUND(product_revenue * 100.0 / SUM(product_revenue) OVER (), 1) AS store_share_pct,
        ROW_NUMBER() OVER (
            PARTITION BY category
            ORDER BY product_revenue DESC, id
        ) AS pos
    FROM product_sales
)
SELECT category, title, is_hit, product_revenue, store_share_pct
FROM ranked
WHERE pos = 1
ORDER BY product_revenue DESC;

Лидеры категорий: «Механическая клавиатура» (78 000, 33.6%), «Худи «SQL Master»» (30 000, 12.9%), «Термокружка кодера» (30 000, 12.9%) — все трое с тегом hit!

2.5.7 Повторные покупатели: рост чека и накопительные траты
Финал модуля

Оставь только клиентов, у которых есть минимум 2 оплаченных заказа. Для каждого их оплаченного заказа выведи: очищенное имя (customer_name), порядковый номер покупки клиента (purchase_num: 1, 2, 3…), дату (order_date), сумму заказа (order_total), изменение чека относительно предыдущей покупки этого клиента (diff_from_prev) и накопительную сумму трат клиента (client_running_total с явным ROWS BETWEEN). Отсортируй по customer_name, purchase_num.

Показать ответ
SQL
WITH order_totals AS (
    SELECT
        o.customer_id,
        INITCAP(TRIM(c.full_name))       AS customer_name,
        o.id                             AS order_id,
        o.created_at::date               AS order_date,
        SUM(oi.quantity * oi.unit_price) AS order_total
    FROM orders AS o
    INNER JOIN customers AS c
        ON c.id = o.customer_id
    INNER JOIN order_items AS oi
        ON oi.order_id = o.id
    WHERE o.status = 'paid'
    GROUP BY o.customer_id, c.full_name, o.id, o.created_at
),
enriched AS (
    SELECT
        *,
        COUNT(*) OVER (PARTITION BY customer_id) AS total_orders,
        ROW_NUMBER() OVER (
            PARTITION BY customer_id
            ORDER BY order_date, order_id
        ) AS purchase_num,
        order_total - LAG(order_total) OVER (
            PARTITION BY customer_id
            ORDER BY order_date, order_id
        ) AS diff_from_prev,
        SUM(order_total) OVER (
            PARTITION BY customer_id
            ORDER BY order_date, order_id
            ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
        ) AS client_running_total
    FROM order_totals
)
SELECT
    customer_name,
    purchase_num,
    order_date,
    order_total,
    diff_from_prev,
    client_running_total
FROM enriched
WHERE total_orders >= 2
ORDER BY customer_name, purchase_num;
