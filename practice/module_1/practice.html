Для практики по Модулю 1 рядом с этой страницей лежит готовый SQL-скрипт наполнения базы — 📄 practice/module_1/init.sql. Он создаёт 4 связанные таблицы онлайн-магазина IT-мерча (categories, customers, products, orders) и заполняет их аккуратными тестовыми данными.

Когда запускать init.sql:
  • Для Урока 1.1 он не нужен — там разминка на чистом PostgreSQL.
  • Перед Уроками 1.2, 1.3 и 1.4 запусти init.sql, чтобы таблицы были готовы.
  • Для сброса данных: скрипт можно запускать сколько угодно раз — он сам удалит старые версии этих таблиц и вернёт данные в исходное состояние (особенно удобно после опытов с UPDATE и DELETE!).

1.1.1 Первое сложение
Очень легко

Подсказка: задай имя колонки через AS answer.

1.1.2 Умножение и хитрость деления
Очень легко

Одним запросом SELECT посчитай три значения: 1) 12 * 8 (mult_result), 2) 10 / 4 (int_div), 3) 10.0 / 4 (exact_div). Сравни результат двух делений!

Показать ответ
SQL
SELECT
    12 * 8   AS mult_result,
    10 / 4   AS int_div,    -- 2 (целочисленное деление отбрасывает остаток)
    10.0 / 4 AS exact_div;  -- 2.5 (есть дробная точка — точное деление)
1.1.3 Работа со строками
Очень легко

Одним запросом SELECT выведи: 1) склейку 'Привет, ' и своего имени (через ||, псевдоним greeting), 2) слово 'postgresql' заглавными буквами (upper(), псевдоним loud), 3) длину строки 'база данных' (length(), псевдоним text_len).

Показать ответ
SQL
SELECT

    upper('postgresql')    AS loud,
    length('база данных')  AS text_len;

Очень легко

Одним запросом SELECT покажи: сегодняшнюю дату (current_date → today), дату через 14 дней (in_two_weeks) и дату 7 дней назад (week_ago).

02 Урок 1.2 · Типы данных, ограничения и INSERT (9 заданий)

Перед началом убедись, что выполнен файл practice/module_1/init.sql (см. раздел 00 выше) — в базе уже должны лежать таблицы categories, customers, products и orders. Если захочешь перепройти задания с нуля, просто запусти init.sql повторно.

1.2.1 Почему для денег нужен NUMERIC
Очень легко

Одним запросом SELECT посчитай 0.1 + 0.2 двумя способами: 1) приведя числа к DOUBLE PRECISION (approx_sum), 2) приведя к NUMERIC (exact_sum).

Подсказка: в PostgreSQL приведение типа пишется через двойное двоеточие: 0.1::NUMERIC.

Показать ответ
SQL
SELECT
    0.1::DOUBLE PRECISION + 0.2::DOUBLE PRECISION AS approx_sum,
    0.1::NUMERIC          + 0.2::NUMERIC          AS exact_sum;
1.2.2 Создаём таблицу промокодов (promo_codes)
Базовое

Создай таблицу promo_codes с колонками:

  • id — BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY
  • code — TEXT NOT NULL UNIQUE
  • discount_percent — INT NOT NULL, проверка CHECK от 5 до 50 включительно
  • is_active — BOOLEAN NOT NULL DEFAULT true
  • expires_at — DATE (может быть NULL, если промокод бессрочный)
Показать ответ
SQL
CREATE TABLE promo_codes (
    id               BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    code             TEXT NOT NULL UNIQUE,
    discount_percent INT NOT NULL CHECK (discount_percent BETWEEN 5 AND 50),
    is_active        BOOLEAN NOT NULL DEFAULT true,
    expires_at       DATE
);
1.2.3 Создаём таблицу отзывов со связями (product_reviews)
Базовое

Создай таблицу product_reviews с колонками: id (BIGINT автоинкремент PRIMARY KEY), customer_id (INT NOT NULL, внешний ключ на customers(id) с ON DELETE CASCADE), product_id (INT NOT NULL, внешний ключ на products(id) с ON DELETE CASCADE), rating (INT NOT NULL CHECK от 1 до 5), comment (TEXT), created_at (TIMESTAMPTZ NOT NULL DEFAULT now()).

Бонус: добавь составное ограничение UNIQUE (customer_id, product_id), чтобы один клиент не мог оставить два отзыва на один товар.

Показать ответ
SQL
CREATE TABLE product_reviews (
    id          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    customer_id INT NOT NULL REFERENCES customers(id) ON DELETE CASCADE,
    product_id  INT NOT NULL REFERENCES products(id)  ON DELETE CASCADE,
    rating      INT NOT NULL CHECK (rating BETWEEN 1 AND 5),
    comment     TEXT,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (customer_id, product_id)
);
1.2.4 Вставка одной строки + DEFAULT + RETURNING
Очень легко

Показать ответ

INSERT INTO promo_codes (code, discount_percent, expires_at)
VALUES ('WELCOME10', 10, '2026-12-31')
RETURNING *;

Очень легко

Одним запросом добавь в promo_codes сразу 2 строки: ('STUDENT20', 20, NULL) и ('VIP30', 30, '2027-01-15'). Выведи через RETURNING колонки id, code, discount_percent.

1.2.7 Вежливая вставка (ON CONFLICT DO NOTHING)
Базовое

Вставь в promo_codes две строки: уже существующий ('WELCOME10', 10) и новый ('FRIDAY15', 15). Добавь ON CONFLICT (code) DO NOTHING и RETURNING id, code — убедись, что дубликат тихо пропустился, а новый код добавился.

Показать ответ
SQL
INSERT INTO promo_codes (code, discount_percent) VALUES
    ('WELCOME10', 10),
    ('FRIDAY15',  15)
ON CONFLICT (code) DO NOTHING
RETURNING id, code;

1.2.9 Краш-тест «охранников» базы
Эксперимент

Запусти по очереди 4 «плохих» запроса и посмотри на текст ошибки PostgreSQL (каждый должен упасть — это значит, защита работает!):

  1. Нарушение CHECK: промокод 'FREE99' со скидкой 99%.
  2. Нарушение NOT NULL: вставка в promo_codes без колонки code.
  3. Нарушение FOREIGN KEY: отзыв в product_reviews от клиента id = 999.
  4. Нарушение составного UNIQUE: повторный отзыв от клиента id = 1 на товар id = 1.
Показать ответ
SQL · Запускай по одному
-- 1) Ошибка CHECK (discount_percent BETWEEN 5 AND 50)
INSERT INTO promo_codes (code, discount_percent) VALUES ('FREE99', 99);

-- 2) Ошибка NOT NULL (колонка code обязательна)
INSERT INTO promo_codes (discount_percent) VALUES (15);

-- 3) Ошибка FOREIGN KEY (клиента 999 нет в customers)
INSERT INTO product_reviews (customer_id, product_id, rating) VALUES (999, 1, 5);

-- 4) Ошибка составного UNIQUE (customer_id, product_id)
INSERT INTO product_reviews (customer_id, product_id, rating, comment)
VALUES (1, 1, 5, 'Повторный отзыв');

Очень легко

Показать ответ
SQL

FROM products
WHERE rating IS NOT NULL

1.3.17 Безопасное «не равно» (IS DISTINCT FROM)
Среднее

Найди в products все товары, у которых скидка discount_pct не равна 10 — причём товары с discount_pct IS NULL тоже должны попасть в ответ! Покажи id, title, discount_pct (сортировка по id ASC).

Показать ответ
SQL
SELECT id, title, discount_pct
FROM products
WHERE discount_pct IS DISTINCT FROM 10
ORDER BY id ASC;

Если написать discount_pct <> 10, потеряются 5 товаров с NULL. Оператор IS DISTINCT FROM возвращает все 11 подходящих строк.

1.3.18 Защищаем формулу скидки через COALESCE
Среднее

Для всех активных товаров (is_active = true) из products выведи: title, price, безопасную скидку COALESCE(discount_pct, 0) AS safe_discount и итоговую цену со скидкой final_price, округлённую до 2 знаков (ROUND(price * (100 - COALESCE(discount_pct, 0)) / 100.0, 2)). Отсортируй по final_price ASC, id ASC.

Показать ответ
SQL
SELECT
    title,
    price,
    COALESCE(discount_pct, 0)                                   AS safe_discount,
    ROUND(price * (100 - COALESCE(discount_pct, 0)) / 100.0, 2) AS final_price
FROM products
WHERE is_active = true
ORDER BY final_price ASC, id ASC;

1.4.9 Первый INNER JOIN двух таблиц
Базовое

Соедини products (псевдоним p) и categories (псевдоним c) по условию p.category_id = c.id. Выведи: p.id, p.title, c.name AS category_name, p.price. Отсортируй по p.id ASC.

Обрати внимание: черновик с category_id IS NULL в результат INNER JOIN не попадёт!

Показать ответ
SQL

Базовое

Выведи все активные товары (p.is_active = true), за категории которых отвечает менеджер 'Алина'. Покажи: p.title, c.name AS category_name, c.manager, p.price. Отсортируй от самого дорогого к дешёвому.

Показать ответ
SQL
SELECT
    p.title,
    c.name AS category_name,
    c.manager,
    p.price

INNER JOIN categories AS c

WHERE c.manager = 'Алина'
