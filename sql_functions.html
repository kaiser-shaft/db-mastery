Арсенал функций SQL

Практический справочник часто используемых встроенных функций SQL, которые пригодятся не только в PostgreSQL, но и при переходе на MySQL, SQLite, MS SQL Server, Oracle или ClickHouse. У каждой функции показан живой пример, статус переносимости и частые ловушки диалектов.

01 NULL и условная логика

Базовый набор защиты от пустых значений, деления на ноль и ветвления логики прямо внутри запроса.

COALESCE(a, b, ...) ANSI SQL

Возвращает первый аргумент слева направо, который не равен NULL. Универсальная замена диалектным IFNULL (MySQL/SQLite), ISNULL (MS SQL) и NVL (Oracle).

SQL · Подстановка значения по умолчанию 
SELECT
  name,
  COALESCE(phone, email, 'Нет контакта') AS primary_contact,
  COALESCE(discount, 0) AS discount_pct
FROM customers;
Результат: phone = NULL, email = 'a@b.ru' → 'a@b.ru'
Поддержка: PG ✓ MySQL 8 ✓ SQLite ✓ MS SQL ✓ ClickHouse ✓
Ловушка: все аргументы должны приводиться к одному типу данных — COALESCE(age, 'не указан') упадёт в строгих СУБД (PG, MS SQL), пока число не привести через CAST(age AS VARCHAR).
NULLIF(a, b) ANSI SQL

Возвращает NULL, если a = b, иначе возвращает a. Главный переносимый способ защититься от деления на ноль и превратить пустые строки '' в честный NULL.

SQL · Безопасное деление и очистка пустых строк 
SELECT
  COALESCE(ROUND(revenue / NULLIF(orders_cnt, 0), 2), 0) AS avg_check,
  NULLIF(TRIM(comment), '') AS clean_comment
FROM daily_stats;
Результат: revenue = 1500, orders_cnt = 0 → NULLIF(0, 0) = NULL → 0 (без ошибки!)
Поддержка: PG ✓ MySQL 8 ✓ SQLite ✓ MS SQL ✓ ClickHouse ✓
Паттерн: связка COALESCE(a / NULLIF(b, 0), 0) работает одинаково во всех реляционных СУБД — держите её в мышечной памяти для расчёта конверсий и средних чеков.
CASE WHEN ... THEN ... ELSE ... END ANSI SQL

Универсальное условное выражение («если-то-иначе»). Работает в SELECT, WHERE, ORDER BY, GROUP BY и UPDATE. Заменяет диалектные IF() (MySQL/CH) и IIF() (MS SQL).

SQL · Сегментация заказов по сумме 
SELECT
  id,
  amount,
  CASE
    WHEN amount >= 50000 THEN 'VIP'
    WHEN amount >= 10000 THEN 'Standard'
    ELSE 'Small'
  END AS order_tier
FROM orders;
Результат: amount = 14500 → 'Standard'
Поддержка: PG ✓ MySQL 8 ✓ SQLite ✓ MS SQL ✓ ClickHouse ✓
Ловушка: ветки проверяются строго сверху вниз до первого TRUE; если опустить ELSE, несовпавшие строки получат NULL. Не пишите CASE col WHEN NULL — равенство с NULL не сработает, используйте CASE WHEN col IS NULL.
GREATEST(a, b, ...) / LEAST(a, b, ...) Почти везде

Выбирают наибольшее или наименьшее значение среди нескольких выражений внутри одной строки (в отличие от MAX/MIN, которые схлопывают строки вертикально).

SQL · Ограничение итоговой цены и остатка на складе 
SELECT
  product_id,
  GREATEST(price - COALESCE(coupon, 0), 0) AS final_price,
  LEAST(requested_qty, stock_qty) AS allowed_qty
FROM cart_items;
Результат: price = 500, coupon = 800 → 0 (цена не уходит в минус)
Поддержка: PG ✓ MySQL 8 (NULL!) SQLite: MAX(a,b) / MIN(a,b) MS SQL 2022+ ✓ ClickHouse (2 арг.)
Критическая ловушка по NULL: в PostgreSQL и MS SQL 2022 GREATEST(10, NULL) игнорирует NULL и вернёт 10, а в MySQL 8 и Oracle вернёт NULL! Всегда оборачивайте nullable-колонки в COALESCE.

02 Работа со строками

Очистка пользовательского ввода, поиск подстрок, склейка и форматирование текстов с учётом особенностей кириллицы и UTF-8.

LOWER(str) / UPPER(str) ANSI SQL

Переводят строку в нижний или верхний регистр. Стандартный инструмент для нормализации email, кодов стран и переносимого регистронезависимого поиска.

SQL · Нормализация email и кодов 
SELECT
  LOWER(TRIM(email)) AS normalized_email,
  UPPER(country_code) AS country_iso
FROM customers
WHERE LOWER(email) = 'alex@example.com';
Результат: 'Alex@Example.COM' → 'alex@example.com'
Поддержка: PG ✓ MySQL 8 ✓ SQLite (ASCII) MS SQL ✓ CH: lowerUTF8()
Ловушка кириллицы: в SQLite без расширения ICU встроенный LOWER('Привет') не меняет русские буквы, а в ClickHouse для UTF-8 нужно использовать lowerUTF8() и upperUTF8().
TRIM(str) / LTRIM / RTRIM ANSI SQL

Удаляют лишние пробелы (или указанные символы) в начале и конце строки. LTRIM чистит только слева, RTRIM — только справа.

SQL · Убираем пробелы и крайние слэши 
SELECT
  TRIM(full_name) AS clean_name,
  TRIM(BOTH '/' FROM url_path) AS clean_slug
FROM pages;
Результат: ' /blog/sql/ ' → 'blog/sql'
Поддержка: PG ✓ MySQL 8 ✓ SQLite: TRIM(s, '/') MS SQL 2017+ ✓ ClickHouse ✓
Ловушка: TRIM убирает символы только по краям — двойные пробелы внутри строки остаются на месте (их чистят через REPLACE или REGEXP_REPLACE).
CHAR_LENGTH(str) / LENGTH(str) Почти везде

Возвращают длину строки. В кросс-СУБД запросах критически важно различать длину в символах и длину в байтах.

SQL · Проверка длины названия товара в символах 
SELECT id, title, CHAR_LENGTH(title) AS chars_cnt
FROM products
WHERE CHAR_LENGTH(title) > 40;
Результат: CHAR_LENGTH('Привет') → 6 символов (но 12 байт в UTF-8!)
Поддержка: PG: оба в символах MySQL: CHAR_LENGTH (симв.) / LENGTH (байты) SQLite: LENGTH MS SQL: LEN (без пробелов справа!) CH: lengthUTF8
Две ловушки: в MySQL и ClickHouse LENGTH('Привет') вернёт 12 (байты), а в MS SQL LEN('abc ') вернёт 3, молча отбрасывая хвостовые пробелы.
SUBSTRING(str FROM pos FOR len) ANSI SQL

Вырезает фрагмент строки длиной len, начиная с позиции pos. Альтернативная форма с запятыми SUBSTRING(str, pos, len) поддерживается почти во всех базах.

SQL · Извлечение года и кода партии из артикула 
-- Стандартная ANSI-запись (PG, MySQL) и компактная форма
SELECT
  SUBSTRING(sku FROM 1 FOR 3) AS brand_code,
  SUBSTRING(sku, 5, 4) AS year_part
FROM products;
Результат: sku = 'PRO-2026-XL' → brand_code = 'PRO', year_part = '2026'
Поддержка: PG ✓ (обе формы) MySQL 8 ✓ (обе) SQLite: SUBSTR(s, pos, len) MS SQL: SUBSTRING(s, pos, len) CH: substringUTF8
Ловушка: в SQL индексация символов начинается с 1, а не с 0! В MS SQL третий аргумент (len) обязателен, а в SQLite используется короткое имя SUBSTR.
REPLACE(str, old_sub, new_sub) Почти везде

Заменяет все точные вхождения подстроки old_sub на new_sub. Удобна для быстрой очистки номеров телефонов, SKU и форматирования.

SQL · Очистка телефона от дефисов и пробелов 
SELECT
  REPLACE(REPLACE(phone, '-', ''), ' ', '') AS clean_phone
FROM customers;
Результат: '+7 701-555-01-02' → '+77015550102'
Поддержка: PG ✓ MySQL 8 ✓ SQLite ✓ MS SQL ✓ CH: replaceAll()
Ловушка: REPLACE не понимает регулярные выражения и чувствительна к регистру (кроме MS SQL с CI-коллацией). Для шаблонов используйте REGEXP_REPLACE (PG, MySQL 8, Oracle, CH).
CONCAT(a, b, ...) / CONCAT_WS(sep, ...) / a || b Зависит от СУБД

Склеивают несколько строк в одну. CONCAT_WS («with separator») ставит разделитель между непустыми значениями и аккуратно пропускает NULL.

SQL · Сборка полного имени и адреса без лишних запятых 
SELECT
  CONCAT(first_name, ' ', last_name) AS full_name,
  CONCAT_WS(', ', city, street, apt) AS full_address
FROM customers;
Результат: city = 'Алматы', street = 'Абая 15', apt = NULL → 'Алматы, Абая 15'
Поддержка: PG: CONCAT / || MySQL: CONCAT (|| = OR!) SQLite: только || MS SQL: CONCAT / + CH: concat / ||
Двойная ловушка: 1) В MySQL по умолчанию 'A' || 'B' означает логическое OR и вернёт 0! 2) CONCAT('A', NULL) в PostgreSQL и MS SQL вернёт 'A', а в MySQL и ClickHouse вернёт NULL! Самый предсказуемый вариант с NULL — CONCAT_WS (PG, MySQL, MS SQL) или явный COALESCE.
LEFT(str, n) / RIGHT(str, n) Почти везде

Берут первые n или последние n символов строки. Гораздо читабельнее, чем вычислять смещение внутри SUBSTRING.

SQL · Маскировка карты и префикс артикула 
SELECT
  LEFT(sku, 3) AS category_prefix,
  CONCAT('**** ', RIGHT(card_number, 4)) AS masked_card
FROM payments;
Результат: card_number = '4400112233449876' → '**** 9876'
Поддержка: PG ✓ MySQL 8 ✓ SQLite: SUBSTR(s, 1, n) / SUBSTR(s, -n) MS SQL ✓ CH: leftUTF8 / rightUTF8
Если нужен 100% переносимый код (включая SQLite и Oracle): заменяйте LEFT(s, n) на SUBSTR(s, 1, n).
POSITION(sub IN str) Зависит от СУБД

Возвращает номер первого вхождения подстроки (начиная с 1) или 0, если подстрока не найдена. В паре с SUBSTRING позволяет разбирать строки без регулярных выражений.

SQL · Извлечение почтового домена после символа @ 
-- Стандартная связка (PG, MySQL 8):
SELECT
  email,
  SUBSTRING(email FROM POSITION('@' IN email) + 1) AS email_domain
FROM customers;
Результат: 'maria@mail.kz' → POSITION = 6 → 'mail.kz'
Поддержка: PG: POSITION / STRPOS MySQL 8: POSITION / LOCATE SQLite: INSTR(str, sub) MS SQL: CHARINDEX(sub, str) CH: positionUTF8(str, sub)
Ловушка порядка аргументов: в POSITION(sub IN str) и CHARINDEX(sub, str) сначала идёт что ищем, а в INSTR(str, sub), STRPOS(str, sub) и ClickHouse position(str, sub) — сначала где ищем!
LPAD(str, len, pad) / RPAD(str, len, pad) Почти везде

Дополняют строку слева или справа указанным символом до фиксированной длины len. Часто используются для красивых номеров счетов и сортируемых кодов.

SQL · Формирование номера счёта с ведущими нулями 
SELECT
  CONCAT('INV-', LPAD(CAST(id AS VARCHAR(10)), 6, '0')) AS invoice_no
FROM invoices;
Результат: id = 42 → 'INV-000042'
Поддержка: PG ✓ MySQL 8 ✓ SQLite: printf('%06d', id) MS SQL: FORMAT(id, '000000') CH: leftPad()
Ловушка: если исходная строка уже длиннее len, LPAD и RPAD молча обрежут её до len символов! Например, LPAD('1234567', 6, '0') даст '123456'.

03 Математика и приведение типов

Переносимая конвертация типов, округление денежных сумм и защита от скрытых различий в арифметике между СУБД.

CAST(expr AS type) ANSI SQL

Стандартное преобразование значения из одного типа данных в другой. Главная переносимая замена PostgreSQL-синтаксису expr::type.

SQL · Приведение текста к числу и метки времени к дате 
SELECT
  CAST('1490.50' AS DECIMAL(10, 2)) AS parsed_price,
  CAST(created_at AS DATE) AS order_date,
  CAST(id AS CHAR(10)) AS id_text
FROM orders;
Результат: '2026-03-15 13:15:00' → 2026-03-15 (DATE)
Поддержка: PG ✓ (и ::) MySQL 8 ✓ SQLite ✓ MS SQL ✓ (+ TRY_CAST) ClickHouse ✓
Ловушка: оператор :: работает в PostgreSQL и ClickHouse, но вызовет синтаксическую ошибку в MySQL, SQLite и MS SQL. Для строкового типа в CAST учитывайте: MySQL ждёт CHAR, а PG/SQLite/MS SQL — VARCHAR / TEXT.
ROUND(x, digits) ANSI SQL

Округляет число до digits знаков после запятой (при 0 — до целого; при отрицательном числе, например -2, — до сотен).

SQL · Округление до копеек и до сотен 
SELECT
  ROUND(CAST(AVG(price) AS DECIMAL(10, 2)), 2) AS avg_price,
  ROUND(14870, -2) AS rounded_hundreds
FROM products;
Результат: ROUND(14870, -2) → 14900
Поддержка: PG (2 арг. только для NUMERIC) MySQL 8 ✓ SQLite (digits ≥ 0) MS SQL ✓ ClickHouse ✓
Ловушка PostgreSQL: ROUND(double_col, 2) вернёт ошибку function round(double precision, integer) does not exist — сначала приведите число к NUMERIC / DECIMAL.
FLOOR(x) / CEILING(x) ANSI SQL

FLOOR округляет строго вниз до целого, CEILING (сокращённо CEIL) — строго вверх. Идеальны для ценовых корзин и расчёта числа страниц пагинации.

SQL · Ценовые корзины по 1000 и число страниц по 20 записей 
SELECT
  FLOOR(price / 1000) * 1000 AS price_bucket,
  CEILING(COUNT(*) * 1.0 / 20) AS total_pages
FROM products
GROUP BY FLOOR(price / 1000) * 1000;
Результат: price = 3990 → 3000 · 41 строка / 20 → 3 страницы
Поддержка: PG ✓ (CEIL/CEILING) MySQL 8 ✓ SQLite 3.35+ ✓ MS SQL: только CEILING ClickHouse ✓
Нюанс: в MS SQL нет короткого псевдонима CEIL — пишите полное CEILING(), оно работает во всех перечисленных СУБД (кроме Oracle, где только CEIL).
ABS(x) / MOD(a, b) Почти везде

ABS возвращает модуль числа (отклонение без знака), MOD(a, b) или a % b — остаток от деления (проверка чётности, разбиение по бакетам/шардам).

SQL · Отклонение план/факт и распределение по 4 батчам 
SELECT
  id,
  ABS(actual_amount - planned_amount) AS abs_diff,
  MOD(id, 4) AS worker_bucket
FROM shipments;
Результат: ABS(-450) → 450 · MOD(10, 4) → 2
Поддержка: PG: MOD и % MySQL 8: MOD и % SQLite: % (MOD 3.35+) MS SQL: только % CH: % / modulo()
Переносимость: оператор a % b работает в PostgreSQL, MySQL, SQLite, MS SQL и ClickHouse (только Oracle требует MOD(a, b)).
TRUNC(x, n) / TRUNCATE(x, n) Зависит от СУБД

Отбрасывают дробную часть после n-го знака без математического округления (просто отрезают хвост к нулю).

SQL · Отрезаем дробные знаки без округления вверх 
-- PostgreSQL / Oracle / ClickHouse:
SELECT TRUNC(19.987, 2) AS cut_val;      -- 19.98

-- MySQL 8:
-- SELECT TRUNCATE(19.987, 2);           -- 19.98
Разница на минусах: FLOOR(-2.3) → -3 vs TRUNC(-2.3) → -2
Поддержка: PG: TRUNC MySQL 8: TRUNCATE(x, n) SQLite 3.35+: TRUNC(x) MS SQL: ROUND(x, n, 1) CH: trunc(x, n)
Главная арифметическая ловушка разных СУБД — целочисленное деление 10 / 3: в PostgreSQL, SQLite и MS SQL деление целых чисел отбрасывает остаток (10 / 3 = 3, а конверсия 5 / 100 = 0!). В MySQL и ClickHouse результат сразу дробный (3.3333). Чтобы формула работала одинаково везде, умножайте числитель на 1.0: paid * 100.0 / NULLIF(total, 0).

04 Даты и время

Самая «разношёрстная» область SQL: базовые функции стандарта работают почти везде, а усечение, форматирование и разница дат различаются — здесь собраны и стандарт, и готовые аналоги.

CURRENT_DATE / CURRENT_TIMESTAMP ANSI SQL

Возвращают текущую дату и текущую дату со временем. В стандарте ANSI пишутся без скобок, в отличие от NOW() (PG/MySQL/CH) и GETDATE() (MS SQL).

SQL · Метка времени по умолчанию и фильтр за сегодня 
SELECT
  CURRENT_DATE AS report_date,
  CURRENT_TIMESTAMP AS generated_at;
Результат: report_date = 2026-03-15 · generated_at = 2026-03-15 14:22:08+05
Поддержка: PG ✓ MySQL 8 ✓ SQLite ✓ (UTC!) MS SQL: CURRENT_TIMESTAMP (дату через CAST) CH: today() / now()
Ловушка: в SQLite CURRENT_DATE и CURRENT_TIMESTAMP всегда возвращают время по UTC, а не локальное время сервера.
EXTRACT(field FROM dt) ANSI SQL

Извлекает числовую часть даты или времени: YEAR, MONTH, DAY, HOUR, MINUTE.

SQL · Группировка продаж по году и месяцу 
SELECT
  EXTRACT(YEAR FROM created_at) AS yr,
  EXTRACT(MONTH FROM created_at) AS mon,
  COUNT(*) AS orders_cnt
FROM orders
GROUP BY yr, mon
ORDER BY yr, mon;
Результат: '2026-03-15 10:20:00' → yr = 2026, mon = 3
Поддержка: PG ✓ MySQL 8 ✓ SQLite: strftime('%Y', dt) MS SQL: DATEPART(year, dt) ClickHouse ✓
Ловушка индексов: не пишите в WHERE условие EXTRACT(YEAR FROM created_at) = 2026 — обёртка функцией отключает обычный B-Tree индекс! Всегда фильтруйте полуоткрытым диапазоном: created_at >= '2026-01-01' AND created_at < '2027-01-01'.
DATE_TRUNC('month', dt) и аналоги Зависит от СУБД

«Срезает» дату до начала месяца, недели, дня или часа — главный приём для графиков, когорт и отчётов по периодам.

SQL · Приведение к началу месяца в разных СУБД 
-- PostgreSQL / ClickHouse:
SELECT DATE_TRUNC('month', created_at) AS month_start FROM orders;

-- MySQL 8:      DATE_FORMAT(created_at, '%Y-%m-01')
-- SQLite:       strftime('%Y-%m-01', created_at)
-- MS SQL 2022+: DATETRUNC(month, created_at)
Результат: '2026-03-15 17:45:00' → '2026-03-01 00:00:00'
Поддержка: PG: DATE_TRUNC MySQL 8: DATE_FORMAT SQLite: strftime MS SQL: DATETRUNC CH: dateTrunc / toStartOfMonth
Почему DATE_TRUNC лучше форматирования: результат остаётся нативной датой/временем, а не строкой — к нему можно сразу прибавлять интервалы и строить временные оси в BI.
Арифметика дат: INTERVAL / DATE_ADD / DATEDIFF Зависит от СУБД

Прибавление и вычитание отрезков времени (например, «последние 30 дней») и подсчёт числа дней между двумя событиями.

SQL · Сдвиг даты и разница в днях по диалектам 
-- PostgreSQL:
SELECT created_at + INTERVAL '7 days', CAST(paid_at AS DATE) - CAST(created_at AS DATE) FROM orders;

-- MySQL 8:    DATE_ADD(created_at, INTERVAL 7 DAY)   | DATEDIFF(paid_at, created_at)
-- SQLite:     date(created_at, '+7 days')            | julianday(paid_at) - julianday(created_at)
-- MS SQL:     DATEADD(day, 7, created_at)            | DATEDIFF(day, created_at, paid_at)
-- ClickHouse: created_at + INTERVAL 7 DAY            | dateDiff('day', created_at, paid_at)
Результат: 2026-03-01 + 7 дней → 2026-03-08
Поддержка: PG: INTERVAL '7 days' MySQL: INTERVAL 7 DAY SQLite: date(..., '+7 days') MS SQL: DATEADD / DATEDIFF CH: INTERVAL 7 DAY / dateDiff
Коварная разница знака: в MySQL DATEDIFF(a, b) считает a - b (сначала конечная дата), а в MS SQL и ClickHouse DATEDIFF(day, a, b) считает b - a (сначала начальная дата)!
TO_CHAR / DATE_FORMAT / strftime Зависит от СУБД

Превращают дату или число в красиво отформатированную строку для отчётов и витрин (например, '15.03.2026' или '2026-Q1').

SQL · Форматирование даты в вид ДД.ММ.ГГГГ 
-- PostgreSQL / Oracle:
SELECT TO_CHAR(created_at, 'DD.MM.YYYY') AS nice_date FROM orders;

-- MySQL 8:    DATE_FORMAT(created_at, '%d.%m.%Y')
-- SQLite:     strftime('%d.%m.%Y', created_at)
-- MS SQL:     FORMAT(created_at, 'dd.MM.yyyy')
-- ClickHouse: formatDateTime(created_at, '%d.%m.%Y')
Результат: 2026-03-15 → '15.03.2026'
Поддержка: PG/Oracle: TO_CHAR MySQL: DATE_FORMAT SQLite: strftime MS SQL: FORMAT CH: formatDateTime
Ловушка сортировки: формат 'DD.MM.YYYY' сортируется по алфавиту неправильно ('02.05.2026' окажется раньше '15.01.2026'). Сортируйте по исходной дате или по ISO-формату 'YYYY-MM-DD'.

05 Агрегатные функции

Свёртка множества строк в итоговые метрики, переносимая условная агрегация и сборка значений группы в одну строку.

COUNT(*) / COUNT(col) / COUNT(DISTINCT col) ANSI SQL

COUNT(*) считает все строки группы, COUNT(col) — только строки с непустым значением, COUNT(DISTINCT col) — число уникальных значений.

SQL · Три вида подсчёта в одном отчёте 
SELECT
  COUNT(*) AS total_orders,
  COUNT(promo_code) AS orders_with_promo,
  COUNT(DISTINCT customer_id) AS unique_buyers
FROM orders;
Результат: 5 заказов, 2 промокода, 3 разных клиента → 5 | 2 | 3
Поддержка: PG ✓ MySQL 8 ✓ SQLite ✓ MS SQL ✓ ClickHouse ✓ (+ uniqExact)
Классическая ловушка LEFT JOIN: если написать COUNT(*) после LEFT JOIN orders o, клиент без единого заказа получит 1 вместо 0! Всегда считайте по ключу правой таблицы: COUNT(o.id).
SUM(x) / AVG(x) / MIN(x) / MAX(x) ANSI SQL

Четыре базовых агрегата для любых числовых (а MIN/MAX — также для строковых и датовых) колонок. Все четыре автоматически пропускают NULL.

SQL · Сводка по категориям товаров 
SELECT
  category,
  COALESCE(SUM(amount), 0) AS total_revenue,
  ROUND(AVG(amount), 2) AS avg_order,
  MIN(created_at) AS first_sale,
  MAX(created_at) AS last_sale
FROM orders
GROUP BY category;
Нюанс NULL: AVG([10, 20, NULL]) → 15 (а не 10!)
Поддержка: PG ✓ MySQL 8 ✓ SQLite ✓ MS SQL ✓ ClickHouse ✓
Ловушка: если NULL в колонке означает «0 рублей», AVG(col) завысит среднее — пишите AVG(COALESCE(col, 0)). Также на пустой выборке SUM вернёт NULL (кроме ClickHouse, где sum даёт 0).
SUM(CASE WHEN cond THEN val ELSE 0 END) ANSI SQL

Условная агрегация — позволяет за один проход по таблице посчитать несколько метрик с разными условиями (воронка, разбивка по статусам, сводная таблица). Работает везде, в отличие от FILTER (WHERE ...).

SQL · Портативная разбивка заказов по статусам 
SELECT
  city,
  COUNT(*) AS total_orders,
  SUM(CASE WHEN status = 'paid' THEN 1 ELSE 0 END) AS paid_cnt,
  SUM(CASE WHEN status = 'paid' THEN amount ELSE 0 END) AS paid_revenue,
  COUNT(CASE WHEN status = 'cancelled' THEN 1 END) AS cancelled_cnt
FROM orders
GROUP BY city;
Результат: 1 проход по таблице → сразу 4 колонки метрик по каждому городу
Поддержка: PG ✓ (+ FILTER) MySQL 8 ✓ SQLite ✓ (+ FILTER) MS SQL ✓ ClickHouse ✓ (+ sumIf/countIf)
Частая ошибка: внутри COUNT(CASE WHEN ... THEN 1 END) нельзя писать ELSE 0 — функция COUNT считает любые не-NULL значения, включая ноль! Для COUNT оставляйте NULL, для SUM пишите ELSE 0.
STRING_AGG / GROUP_CONCAT / LISTAGG Зависит от СУБД

Собирают значения из нескольких строк одной группы в единую строку через разделитель (например, список всех товаров в заказе или тегов статьи).

SQL · Сбор позиций каждого заказа в одну строку 
-- PostgreSQL / SQLite 3.44+:
SELECT order_id, STRING_AGG(title, ', ' ORDER BY title) AS items_list
FROM order_items GROUP BY order_id;

-- MySQL 8:    GROUP_CONCAT(title ORDER BY title SEPARATOR ', ')
-- MS SQL:     STRING_AGG(title, ', ') WITHIN GROUP (ORDER BY title)
-- Oracle:     LISTAGG(title, ', ') WITHIN GROUP (ORDER BY title)
-- ClickHouse: arrayStringConcat(groupArray(title), ', ')
Результат: 3 строки ('Худи', 'Кружка', 'Стикер') → 'Кружка, Стикер, Худи'
Поддержка: PG: STRING_AGG MySQL 8: GROUP_CONCAT SQLite: GROUP_CONCAT / STRING_AGG MS SQL 2017+: STRING_AGG CH: arrayStringConcat
Ловушка MySQL: GROUP_CONCAT по умолчанию молча обрезает итоговую строку на длине 1024 байта (лечится параметром group_concat_max_len). А без ORDER BY порядок склейки не гарантирован.

06 Оконные функции (стандарт SQL:2003)

Аналитика поверх строк без их схлопывания: рейтинги, сравнение с предыдущим периодом, накопительные итоги и разбиение на квантили. Сегодня поддерживаются во всех основных СУБД.

ROW_NUMBER() / RANK() / DENSE_RANK() ANSI SQL

Нумеруют строки внутри каждой группы (PARTITION BY): ROW_NUMBER даёт строго уникальные номера 1,2,3,4; RANK оставляет пропуск после дублей 1,2,2,4; DENSE_RANK не пропускает 1,2,2,3.

SQL · Топ-3 самых дорогих товара в каждой категории 
WITH ranked AS (
  SELECT
    category, title, price,
    ROW_NUMBER() OVER (PARTITION BY category ORDER BY price DESC, id) AS rn
  FROM products
)
SELECT category, title, price
FROM ranked
WHERE rn <= 3;
Ничья (100, 90, 90, 80): ROW_NUMBER → 1,2,3,4 · RANK → 1,2,2,4 · DENSE_RANK → 1,2,2,3
Поддержка: PG ✓ MySQL 8+ ✓ SQLite 3.25+ ✓ MS SQL ✓ ClickHouse ✓
Две ловушки: 1) Фильтровать оконную функцию в WHERE напрямую нельзя — выносите её в CTE/подзапрос. 2) Для ROW_NUMBER() всегда добавляйте уникальный tie-breaker (например, id) в ORDER BY.
LAG(col, offset, default) / LEAD(col, offset, default) ANSI SQL

Заглядывают в предыдущую (LAG) или следующую (LEAD) строку окна без дорогих самосоединений (SELF JOIN). Незаменимы для расчёта роста MoM/YoY и пауз между событиями.

SQL · Прирост выручки по сравнению с прошлым месяцем 
SELECT
  month_start,
  revenue,
  LAG(revenue, 1) OVER (ORDER BY month_start) AS prev_revenue,
  ROUND(
    (revenue - LAG(revenue, 1) OVER (ORDER BY month_start)) * 100.0
    / NULLIF(LAG(revenue, 1) OVER (ORDER BY month_start), 0),
    1
  ) AS mom_pct
FROM monthly_sales;
Результат: янв = 100, фев = 125 → prev = 100, mom_pct = +25.0%
Поддержка: PG ✓ MySQL 8+ ✓ SQLite 3.25+ ✓ MS SQL ✓ CH: lagInFrame / leadInFrame
Нюанс ClickHouse: вместо LAG/LEAD там используются lagInFrame и leadInFrame (причём для leadInFrame нужно явно расширить рамку до UNBOUNDED FOLLOWING).
SUM(x) / AVG(x) OVER (PARTITION BY ... ORDER BY ... ROWS BETWEEN ...) ANSI SQL

Оконные агрегаты считают накопительный итог, скользящее среднее за N строк и долю каждой строки в общей сумме без потери детализации.

SQL · Накопительный итог, скользящее среднее за 3 дня и доля 
SELECT
  sale_date,
  revenue,
  SUM(revenue) OVER (ORDER BY sale_date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_total,
  ROUND(AVG(revenue) OVER (ORDER BY sale_date ROWS BETWEEN 2 PRECEDING AND CURRENT ROW), 2) AS ma_3d,
  ROUND(revenue * 100.0 / NULLIF(SUM(revenue) OVER (), 0), 2) AS share_pct
FROM daily_sales;
Результат: [10, 20, 30] → running_total: [10, 30, 60] · ma_3d: [10, 15, 20]
Поддержка: PG ✓ MySQL 8+ ✓ SQLite 3.25+ ✓ MS SQL ✓ ClickHouse ✓
Ловушка RANGE по умолчанию: если написать просто SUM(x) OVER (ORDER BY dt) без ROWS BETWEEN, стандарт применяет RANGE и суммирует все строки с одинаковой датой dt сразу. Для строго построчного накопления всегда указывайте ROWS BETWEEN.
FIRST_VALUE(col) / LAST_VALUE(col) ANSI SQL

Возвращают первое или последнее значение в текущей рамке окна — удобно, чтобы рядом с каждым заказом вывести сумму первой или последней покупки клиента.

SQL · Сравнение заказа с первым и последним заказом клиента 
SELECT
  customer_id, created_at, amount,
  FIRST_VALUE(amount) OVER (
    PARTITION BY customer_id ORDER BY created_at
  ) AS first_amt,
  LAST_VALUE(amount) OVER (
    PARTITION BY customer_id ORDER BY created_at
    ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
  ) AS last_amt
FROM orders;
Результат: заказы клиента [1000, 2500, 4000] → first_amt = 1000, last_amt = 4000
Поддержка: PG ✓ MySQL 8+ ✓ SQLite 3.25+ ✓ MS SQL ✓ ClickHouse ✓
Самая частая ловушка оконных функций: без явного ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING рамка заканчивается на текущей строке, поэтому LAST_VALUE(amount) будет возвращать просто текущее значение amount!
NTILE(n) ANSI SQL

Делит отсортированный набор строк на n примерно равных корзин (квартили при n=4, децили при n=10). Классика для RFM-анализа и сегментации клиентов.

SQL · Разбиение клиентов на 4 равных квартиля по тратам 
SELECT
  customer_id,
  total_spent,
  NTILE(4) OVER (ORDER BY total_spent DESC) AS spend_quartile
FROM customer_totals;
Результат: топ-25% клиентов → spend_quartile = 1
Поддержка: PG ✓ MySQL 8+ ✓ SQLite 3.25+ ✓ MS SQL ✓ ClickHouse ✓
Нюанс: NTILE делит строго по числу строк, поэтому два клиента с одинаковой суммой на границе могут попасть в соседние квартили. Если важен точный процентиль по значению — используйте PERCENT_RANK().
