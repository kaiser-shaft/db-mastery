01 Боевой датасет маркетплейса в learning_db

Представь, что ты устроился аналитиком данных в интернет-магазин мерча и гаджетов. В первый же рабочий день руководитель присылает список вопросов: «Кто наши VIP-клиенты, а кто так ничего и не купил? Как меняется выручка по месяцам? Какие товары с тегом hit приносят больше всего денег?».

В реальной жизни данные не бывают идеальными: у кого-то в имени лишние пробелы, один клиент зарегистрировался и не сделал ни одного заказа, другой заказ отменил, а свойства товаров и доставки лежат в JSONB. Сначала посмотрим на схему связей нашей базы:

CREATE TABLE products (
  id SERIAL PRIMARY KEY,
  title TEXT NOT NULL,

);

02 Кейс 1: Сегментация всех клиентов (LEFT JOIN + CASE + строки)

Первая задача от маркетинга: «Покажи ВСЕХ зарегистрированных клиентов, почисти их имена, посчитай число оплаченных заказов, общую сумму трат и раздай статусы: VIP (от 50 000), Активный (меньше 50 000) или Спящий (0 оплаченных покупок)».

Здесь скрыта классическая ловушка: нам нужны все клиенты, включая Данияра (у него нет заказов) и Ольгу (у неё заказ отменён). Значит, условие o.status = 'paid' нужно ставить внутрь ON при LEFT JOIN, а не в WHERE — иначе «спящие» клиенты просто исчезнут из отчёта!

SQL · Кейс 1 — Полная витрина клиентов со статусами 
-- Собираем профиль каждого клиента, не теряя тех, у кого нет оплаченных заказов
SELECT
  INITCAP(TRIM(c.full_name)) AS customer_name,
  COALESCE(c.city, 'Не указан') AS city,
  COUNT(DISTINCT o.id) AS paid_orders,
  COALESCE(SUM(oi.quantity * oi.unit_price), 0) AS total_spent,
  CASE
    WHEN COALESCE(SUM(oi.quantity * oi.unit_price), 0) >= 50000 THEN 'VIP'
    WHEN COALESCE(SUM(oi.quantity * oi.unit_price), 0) > 0      THEN 'Активный'
    ELSE 'Спящий'
  END AS segment
FROM customers c
LEFT JOIN orders o
  ON o.customer_id = c.id AND o.status = 'paid'
LEFT JOIN order_items oi
  ON oi.order_id = o.id
GROUP BY c.id, c.full_name, c.city
ORDER BY total_spent DESC, c.id;

-----------------+-----------+-------------+-------------+----------

 Мария Смирнова  | Астана    |           2 |    76000.00 | VIP
 Тимур Касымов   | Костанай  |           1 |    18000.00 | Активный
 Елена Волкова   | Алматы    |           1 |    12000.00 | Активный

Отчёт получился идеальным: имя Алексея очистилось от пробелов, пустой город Данияра превратился в Не указан, отменённый заказ Ольги не попал в выручку, а оба «спящих» клиента остались в таблице с нулями.

03 Кейс 2: Финансовый дашборд по месяцам (CTE + даты + окна)

Вторая задача от финансового директора: «Собери помесячный отчёт за 1-й квартал 2026 года: выручка месяца, сколько из неё принесли экспресс-доставки (JSONB), разница с прошлым месяцем (LAG) и накопительная выручка с начала года».

Такой запрос кажется огромным, пока не разобьёшь его на два простых шага через CTE:

SQL · Кейс 2 — Помесячная выручка, экспресс-доставки и динамика 
-- Шаг 1: считаем общую выручку и выручку экспресс-заказов по месяцам
WITH monthly AS (
  SELECT
    DATE_TRUNC('month', o.created_at)::date AS sales_month,
    SUM(oi.quantity * oi.unit_price) AS revenue,
    COALESCE(
      SUM(oi.quantity * oi.unit_price)
        FILTER (WHERE o.delivery_info @> '{"express": true}'::jsonb),
      0
    ) AS express_revenue
  FROM orders o
  JOIN order_items oi ON oi.order_id = o.id
  WHERE o.status = 'paid'
    AND o.created_at >= TIMESTAMPTZ '2026-01-01 00:00:00+05'
    AND o.created_at <  TIMESTAMPTZ '2026-04-01 00:00:00+05'
  GROUP BY sales_month
)
-- Шаг 2: добавляем динамику к прошлому месяцу и накопительный итог
SELECT
  sales_month,
  revenue,
  express_revenue,
  revenue - LAG(revenue) OVER (ORDER BY sales_month) AS diff_prev_month,
  SUM(revenue) OVER (
    ORDER BY sales_month
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
  ) AS running_total
FROM monthly
ORDER BY sales_month;
Ответ PostgreSQL
 sales_month | revenue  | express_revenue | diff_prev_month | running_total
-------------+----------+-----------------+-----------------+---------------
 2026-01-01  | 59000.00 |        19000.00 |                 |      59000.00
 2026-02-01  | 48000.00 |        30000.00 |       -11000.00 |     107000.00
 2026-03-01  | 88000.00 |        76000.00 |        40000.00 |     195000.00
(3 rows)

Обрати внимание на элегантную фишку PostgreSQL: SUM(...) FILTER (WHERE ...) работает так же, как CASE WHEN внутри SUM, но читается намного чище. За один запрос директор видит и просадку в феврале (-11000.00), и взрывной рост в марте (+40000.00), и то, что почти вся мартовская выручка (76000.00 из 88000.00) пришла через экспресс-доставку!

04 Кейс 3: Рейтинг товаров-хитов по выручке (JSONB + окна)

Третья задача от отдела закупок: «Покажи самый прибыльный товар в каждой категории среди оплаченных заказов, его долю в выручке магазина и отметь, есть ли у него тег "hit" в JSONB».

SQL · Кейс 3 — Лидер продаж в каждой категории 
-- Шаг 1: считаем фактическую выручку каждого товара по оплаченным заказам
WITH product_sales AS (
  SELECT
    p.id,
    p.category,
    p.title,
    (p.specs @> '{"tags": ["hit"]}'::jsonb) AS is_hit,
    SUM(oi.quantity * oi.unit_price) AS product_revenue
  FROM products p
  JOIN order_items oi ON oi.product_id = p.id
  JOIN orders o ON o.id = oi.order_id
  WHERE o.status = 'paid'
  GROUP BY p.id, p.category, p.title, p.specs
),
-- Шаг 2: нумеруем товары внутри категории и считаем долю в общей кассе
ranked AS (
  SELECT
    *,
    ROUND(product_revenue * 100.0 / SUM(product_revenue) OVER (), 1) AS store_share_pct,
    ROW_NUMBER() OVER (
      PARTITION BY category
      ORDER BY product_revenue DESC, id
    ) AS pos
  FROM product_sales
)
SELECT category, title, is_hit, product_revenue, store_share_pct
FROM ranked
WHERE pos = 1
ORDER BY product_revenue DESC;
Ответ PostgreSQL
  category  |          title          | is_hit | product_revenue | store_share_pct
------------+-------------------------+--------+-----------------+-----------------
 Гаджеты    | Механическая клавиатура | t      |        80000.00 |            41.0
 Мерч       | Худи «SQL Master»       | t      |        45000.00 |            23.1
 Аксессуары | Термокружка кодера      | t      |        24000.00 |            12.3
(3 rows)

Все три лидера категорий действительно имеют тег hit (t — true), а одна только механическая клавиатура приносит 41.0% всей выручки магазина!

05 Две главные ловушки комплексных запросов

Даже опытные разработчики иногда попадаются на двух классических ошибках, когда объединяют LEFT JOIN, GROUP BY и оконные функции. Запомни их раз и навсегда:

✗ Как НЕ надо (убили LEFT JOIN)
SELECT c.full_name, COUNT(o.id)
FROM customers c
LEFT JOIN orders o
  ON o.customer_id = c.id
WHERE o.status = 'paid'
GROUP BY c.id, c.full_name;

Условие по правой таблице в WHERE выбрасывает всех клиентов без заказов, превращая LEFT JOIN в обычный INNER JOIN.

✓ Как правильно
SELECT c.full_name, COUNT(o.id)
FROM customers c
LEFT JOIN orders o
  ON o.customer_id = c.id
 AND o.status = 'paid'
GROUP BY c.id, c.full_name;

Фильтр o.status = 'paid' перенесён в ON: все клиенты остаются на месте, а отменённые заказы не считаются.

Вторая частая ошибка — забыть, что после GROUP BY в оконной функции можно обращаться только к сгруппированным колонкам или агрегатам:

SQL · Ошибка смешивания GROUP BY и неагрегированной колонки 
-- ОШИБКА: unit_price не входит в GROUP BY и не обёрнут в агрегат
SELECT
  o.customer_id,
  SUM(oi.unit_price) OVER (ORDER BY o.customer_id)
FROM orders o
JOIN order_items oi ON oi.order_id = o.id
GROUP BY o.customer_id;
Ошибка PostgreSQL
ERROR:  column "oi.unit_price" must appear in the GROUP BY clause or be used in an aggregate function
Золотое правило для сложных запросов: Никогда не пытайся засунуть GROUP BY и оконные функции в один запутанный SELECT. Сделай шаг 1 в CTE (посчитай суммы через GROUP BY), а в шаге 2 спокойно вешай сверху любые ROW_NUMBER(), LAG() и SUM() OVER.

06 Чек-лист перед самостоятельным чекпоинтом

Перед тем как приступить к 4 финальным задачам Модуля 2, проверь свой «инженерный рюкзак»:

  • Нужны «все» записи слева (даже с нулями)? Используй LEFT JOIN, фильтр правой таблицы ставь в ON, а пустые суммы оборачивай в COALESCE(..., 0).
  • Запрос состоит из 2+ логических этапов? Сразу пиши WITH step1 AS (...), step2 AS (...) — отлаживать по шагам в разы проще.
  • Нужен «Топ-N в группе» или сравнение с прошлым? Считай ROW_NUMBER() / LAG() в CTE и фильтруй результат во внешнем WHERE.
  • Работаешь с JSONB? Для проверки наличия ключа/тега бери @>, для чтения текста — ->>, для чисел добавляй ::int.

07 Итоговый чекпоинт Модуля 2 (4 задачи)

Выполни все 4 автономные задачи на датасете из Раздела 01 в базе learning_db. Старайся сначала получить ответ самостоятельно, проверяя промежуточные шаги в psql, и только потом открывай эталонное решение.

Задача 1 (Базовый). Непроданные или непопулярные товары

Выведи все товары из таблицы products, количество проданных штук (units_sold) по оплаченным заказам и общую выручку по товару (revenue). Оставь только те товары, которых продано меньше 3 штук (включая 0, если такие появятся). Отсортируй по возрастанию units_sold, затем по id.

Показать решение
SQL · Решение задачи 1 
SELECT
  p.title,
  p.category,
  COALESCE(SUM(oi.quantity), 0) AS units_sold,
  COALESCE(SUM(oi.quantity * oi.unit_price), 0) AS revenue
FROM products p
LEFT JOIN order_items oi ON oi.product_id = p.id
LEFT JOIN orders o
  ON o.id = oi.order_id AND o.status = 'paid'
WHERE o.id IS NOT NULL OR oi.id IS NULL
GROUP BY p.id, p.title, p.category
HAVING COALESCE(SUM(oi.quantity), 0) < 3
ORDER BY units_sold ASC, p.id;
Задача 2 (Средний). Эффективность служб доставки из JSONB

Сгруппируй все оплаченные заказы по названию курьерской службы (delivery_info ->> 'courier'). Выведи службу доставки, количество заказов, общую выручку и средний чек заказа (avg_order_total, округлённый до 2 знаков). Подсказка: сначала посчитай сумму каждого заказа в CTE, чтобы AVG считался именно по заказам, а не по позициям!

Показать решение
SQL · Решение задачи 2 
WITH order_totals AS (
  SELECT
    o.id AS order_id,
    o.delivery_info ->> 'courier' AS courier,
    SUM(oi.quantity * oi.unit_price) AS order_total
  FROM orders o
  JOIN order_items oi ON oi.order_id = o.id
  WHERE o.status = 'paid'
  GROUP BY o.id, o.delivery_info
)
SELECT
  courier,
  COUNT(*) AS orders_count,
  SUM(order_total) AS total_revenue,
  ROUND(AVG(order_total), 2) AS avg_order_total
FROM order_totals
GROUP BY courier
ORDER BY total_revenue DESC;
Задача 3 (Средний). Почтовые домены и средний чек

Извлеки почтовый домен каждого клиента (часть email после @ в нижнем регистре). Посчитай для каждого домена: сколько всего клиентов с этим доменом зарегистрировано и какую суммарную выручку принесли их оплаченные заказы. Выведи только домены с ненулевой выручкой, отсортировав по убыванию выручки.

Показать решение
SQL · Решение задачи 3 
SELECT
  SPLIT_PART(LOWER(c.email), '@', 2) AS email_domain,
  COUNT(DISTINCT c.id) AS customers_count,
  COALESCE(SUM(oi.quantity * oi.unit_price), 0) AS total_revenue
FROM customers c
LEFT JOIN orders o
  ON o.customer_id = c.id AND o.status = 'paid'
LEFT JOIN order_items oi
  ON oi.order_id = o.id
GROUP BY email_domain
HAVING COALESCE(SUM(oi.quantity * oi.unit_price), 0) > 0
ORDER BY total_revenue DESC;
Задача 4 (Продвинутый). Повторные покупатели и рост их чека

Найди всех клиентов, у которых есть минимум 2 оплаченных заказа. Для каждого их заказа выведи: очищенное имя клиента, порядковый номер покупки этого клиента (purchase_num: 1, 2, 3...), дату заказа, сумму заказа и изменение суммы по сравнению с его предыдущим заказом (diff_from_prev).

Показать решение
SQL · Решение задачи 4 
WITH order_totals AS (
  SELECT
    o.customer_id,
    INITCAP(TRIM(c.full_name)) AS customer_name,
    o.id AS order_id,
    o.created_at::date AS order_date,
    SUM(oi.quantity * oi.unit_price) AS order_total
  FROM orders o
  JOIN customers c ON c.id = o.customer_id
  JOIN order_items oi ON oi.order_id = o.id
  WHERE o.status = 'paid'
  GROUP BY o.customer_id, c.full_name, o.id, o.created_at
),
enriched AS (
  SELECT
    *,
    COUNT(*) OVER (PARTITION BY customer_id) AS total_orders,
    ROW_NUMBER() OVER (PARTITION BY customer_id ORDER BY order_date, order_id) AS purchase_num,
    order_total - LAG(order_total) OVER (
      PARTITION BY customer_id ORDER BY order_date, order_id
    ) AS diff_from_prev
  FROM order_totals
)
SELECT
  customer_name,
  purchase_num,
  order_date,
  order_total,
  diff_from_prev
FROM enriched
WHERE total_orders >= 2
ORDER BY customer_name, purchase_num;

Все твои запросы уже дают правильный ответ — а в следующем Модуле 3 мы научимся делать так, чтобы они работали мгновенно даже на десятках миллионов строк: разберём устройство индексов (B-Tree, GIN), чтение планов EXPLAIN ANALYZE и надёжные транзакции!
