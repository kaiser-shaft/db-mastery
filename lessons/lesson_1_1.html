Как устроены реляционные БД и запуск PostgreSQL

Главное в этом уроке
  • Поймём на живых примерах, зачем миру нужны базы данных, если уже есть Excel и обычный Блокнот.
  • Разберёмся, как таблицы связываются между собой через ключи (на примере школьной пиццерии).
  • Запомним «матрёшку» PostgreSQL: Кластер → База данных → Схема → Таблица.
  • Запустим свой собственный сервер PostgreSQL 16 в Docker за пару минут, подключимся через psql и напишем первые SQL-запросы.

01 Зачем нужна база данных, если есть Excel?

Представь, что вы с друзьями открыли маленький онлайн-магазин школьного мерча: продаёте худи, стикеры и значки. Сначала заказов немного — 5 штук в день. Вы записываете их в обычный файл Excel: кто купил, что купил, заплатил ли. Всё работает отлично!

А теперь представь, что о магазине узнала вся страна, и к вам на сайт одновременно зашли 5 000 человек. В этот момент обычный файл Excel или текстовый orders.txt превращается в катастрофу.

✗ Файл Excel / CSV

Толкучка: Петя и Маша одновременно купили последний значок — оба увидели «остался 1» и перезаписали файл друг другу.

Тормоза: На 2 миллионах строк файл будет открываться минутами.

Мусор: В колонку «Цена» кто-то вписал текст «договоримся», и формулы сломались.

✓ СУБД (PostgreSQL)

Порядок в очереди: тысячи людей работают одновременно, и никто не портит чужие записи.

Молниеносный поиск: находит нужный заказ среди миллионов за 0.001 секунды.

Строгий контроль: не пропустит текст туда, где должно быть число, и сохранит данные даже при отключении света.

Простая аналогия (БД vs СУБД): Представь огромную библиотеку. Сами книги и карточки читателей — это база данных (БД). А супер-библиотекарь со сверхскоростью, который мгновенно находит нужную книгу и следит за порядком на полках, — это СУБД (система управления базами данных, в нашем курсе — PostgreSQL).

02 Реляционные БД на примере пиццерии

Слово «реляционная» звучит сложно, но на деле всё просто: так называют базы, в которых данные разложены по таблицам (математики называют таблицу словом relation — «отношение»), а сами таблицы связаны между собой.

Почему нельзя сложить всё в одну огромную таблицу?

Допустим, мы делаем базу для пиццерии и решили записывать всё в одну таблицу:

№ заказа Имя клиента Телефон Адрес Пицца Цена
101 Артём +7-701-111-22-33 ул. Абая, 15 Пепперони 3500
102 Артём +7-701-111-22-33 ул. Абая, 15 Маргарита 2900
103 Артём +7-701-111-22-33 ул. Абая, 15 Четыре сыра 3800

Посмотри, что здесь не так: Артём любит пиццу и за год сделал 50 заказов. Каждый раз мы заново пишем его имя, телефон и адрес. Если Артём переедет на другую улицу, придётся искать и исправлять все 50 строк. Пропустим хоть одну — курьер уедет по старому адресу!

Решение: разделяем на две таблицы и связываем их «номерками»

В реляционной базе мы создадим две аккуратные таблицы: отдельно клиенты (customers) и отдельно заказы (orders). Каждому клиенту выдадим уникальный номер id (как номер паспорта), а в заказах будем указывать только этот номер!

Мини-словарь терминов (запоминаем раз и навсегда)

Термин Простыми словами Пример из пиццерии
Таблица (table) Отдельная тетрадь для одного типа объектов. customers (клиенты) и orders (заказы).
Столбец / колонка (column) Свойство объекта со строгим типом данных (число, текст, дата). name (текст), price (число).
Строка / запись (row) Один конкретный объект в таблице. Запись про Алину или заказ №103.
Первичный ключ (PRIMARY KEY) Уникальный «паспорт» строки. Двух одинаковых номеров быть не может. Колонка id в таблице customers.
Внешний ключ (FOREIGN KEY) «Стрелочка», указывающая на первичный ключ в другой таблице. Не позволит создать заказ для несуществующего клиента №999. Колонка customer_id в таблице orders.
Важное отличие от Excel: В базе данных строки хранятся как шарики в коробке, а не по порядку «строка 1, строка 2, строка 3». Сегодня PostgreSQL может вернуть Артёма первым, а завтра — Алину. Если нужен конкретный порядок, его всегда задают командой ORDER BY.

03 Как устроен PostgreSQL: ресторан и матрёшка

PostgreSQL работает как ресторан (инженеры называют это клиент-серверной архитектурой):

  • Сервер PostgreSQL — это «кухня». Она постоянно работает в фоне и ждёт заказов на специальном «окошке выдачи» — сетевом порту 5432.
  • Клиент — это «гость» (терминальная программа psql, графический редактор DBeaver или твой сайт на Python/JS).
  • SQL — это язык, на котором гость делает заказ кухне (например: «Принеси мне все заказы дороже 3000»).

Четыре уровня «матрёшки» PostgreSQL

Уровень Аналогия со школой Как это работает в PostgreSQL
1. Кластер (Cluster) Всё здание школы Один запущенный сервер PostgreSQL. Общий список пользователей и общая папка файлов на диске.
2. База данных (Database) Отдельный кабинет (физика, информатика) Изолированный проект внутри сервера (например, learning_db). Подключаясь, ты всегда заходишь в одну конкретную базу.
3. Схема (Schema) Полки в шкафу внутри кабинета Папки для порядка внутри одной базы. По умолчанию всё складывается в схему public.
4. Таблица (Table) Конкретный журнал на полке Сами таблицы с данными (например, public.customers).
Полезно знать на будущее: В другой популярной СУБД — MySQL — понятия «база данных» и «схема» означают одно и то же. В PostgreSQL это два разных уровня: внутри одной базы может жить хоть 20 схем, и ты легко объединяешь таблицы из разных схем в одном запросе.

04 Запускаем свой PostgreSQL 16 в Docker

Обычные программы ставят прямо на Windows или macOS. С базами данных инженеры поступают хитрее — запускают их в Docker. Представь, что Docker-контейнер — это отдельная игровая приставка в коробке: включил в розетку, и внутри уже идеально настроенный PostgreSQL 16. А чтобы таблицы не пропали при выключении приставки, мы подключаем к ней «флешку с сохранениями» — volume (том).

Шаг 1. Знакомимся с файлом docker-compose.yaml

В корневой папке нашего курса уже лежит готовый файл docker-compose.yaml. Вот как в нём устроен наш базовый сервис pg_primary (основной PostgreSQL 16):

YAML · Фрагмент docker-compose.yaml (сервис pg_primary) 
services:
  pg_primary:
    # Официальный образ PostgreSQL 16-й версии
    image: postgres:16
    container_name: course_pg_primary
    restart: unless-stopped
    environment:
      POSTGRES_DB: learning_db            # База, которая создастся сама
      POSTGRES_USER: student              # Логин администратора
      POSTGRES_PASSWORD: student_pass     # Пароль для локальной учёбы
    # Пробрасываем «окошко» (порт 5432 на твоём ПК -> порт 5432 в контейнере)
    ports:
      - "5432:5432"
    # Подключаем «флешку с сохранениями» к папке с данными PostgreSQL
    volumes:
      - pg_primary_data:/var/lib/postgresql/data
      - ./backups:/backups
    # Автопроверка каждые 5 секунд: готов ли сервер принимать подключения
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U student -d learning_db"]
      interval: 5s
      timeout: 5s
      retries: 10

volumes:
  pg_primary_data:

Шаг 2. Запускаем контейнер и проверяем здоровье

Убедись, что запущен Docker Desktop, открой терминал в папке курса (где лежит docker-compose.yaml) и выполни:

BASH 
# 1. Скачать образ (только в первый раз) и запустить сервер в фоне (-d)
docker compose up -d

# 2. Проверить статус контейнера
docker compose ps
Ответ терминала
NAME                IMAGE         STATUS                    PORTS
course_pg_primary   postgres:16   Up 12 seconds (healthy)   0.0.0.0:5432->5432/tcp

Слово (healthy) означает, что сервер проснулся и готов к работе! Когда закончишь заниматься, можешь поставить его на паузу командой docker compose stop, а на следующий день снова включить через docker compose start.

Не нажимай «красную кнопку» случайно! Команда docker compose down удаляет контейнер, но оставляет твою «флешку» (volume) с таблицами. А вот команда с флагом -v (docker compose down -v) стирает и саму флешку!
Если порт 5432 уже занят: Если Docker пишет port is already allocated, просто поменяй в docker-compose.yaml строчку на - "55432:5432" и снова выполни docker compose up -d.

05 Первые шаги в psql: много практических примеров

Зайдём внутрь нашего сервера через главный консольный пульт управления — программу psql (она уже есть внутри контейнера):

BASH 
docker exec -it course_pg_primary psql -U student -d learning_db

Ты увидишь приглашение learning_db=#. Оно говорит, что ты подключён к базе learning_db с правами суперпользователя (значок #).

✗ Забыл точку с запятой в SQL
learning_db=# SELECT 2 + 2
learning_db-#

Знак = сменился на -: psql думает, что ты ещё не дописал команду, и ждёт продолжения. Просто допиши ; и нажми Enter!

✓ Запомни простое правило
learning_db=# SELECT 2 + 2;
learning_db=# \l

SQL-запросы всегда заканчиваются ;. Мета-команды со слэшем \ выполняются сразу без ;.

Пример 1. Осматриваемся вокруг (главные мета-команды psql)

Команда Как запомнить Что покажет
\l (или \l+) list Список всех баз данных на сервере (+ добавляет размер на диске).
\c имя_бд connect Перейти в другую базу данных (например, \c postgres).
\dn display namespaces Список схем («полок») в текущей базе. Сейчас там public.
\dt display tables Список всех таблиц в текущей базе.
\d имя_табл describe «Рентген-карта» таблицы: колонки, типы данных и ключи.
\timing таймер Включает секундомер: после каждого запроса увидишь время в миллисекундах.
\q quit Выход из psql обратно в обычный терминал.

Пример 2. PostgreSQL как калькулятор (хитрость с делением!)

Команда SELECT («покажи») умеет считать даже без таблиц. Попробуй выполнить этот запрос и обрати внимание на разницу между 10 / 3 и 10.0 / 3:

SQL · Математика и псевдонимы AS 
-- Слово AS даёт колонке красивое понятное имя в ответе
SELECT
    2 + 2 * 2 AS school_math,
    2 ^ 10    AS power_of_two,
    10 / 3    AS int_division,   -- оба числа целые -> остаток просто отбросится!
    10.0 / 3  AS exact_division; -- есть дробная точка -> точное деление
Ответ PostgreSQL
 school_math | power_of_two | int_division |   exact_division
-------------+--------------+--------------+--------------------
           6 |         1024 |            3 | 3.3333333333333333
(1 row)

Пример 3. Работа со строками и датами

SQL · Текст и календарь 
-- Оператор || склеивает кусочки текста в одну строку
SELECT
    'Привет, ' || 'PostgreSQL!' AS greeting,
    upper('база данных')        AS loud_text,
    length('PostgreSQL')        AS letters_count,
    current_date                AS today,
    current_date + 7            AS next_week;
Ответ PostgreSQL
       greeting       |  loud_text  | letters_count |   today    | next_week
----------------------+-------------+---------------+------------+------------
 Привет, PostgreSQL!  | БАЗА ДАННЫХ |            10 | 2026-11-25 | 2026-12-02
(1 row)

Пример 5. Тест-драйв настоящей таблицы (мини-база игр)

Профессионально проектировать таблицы мы начнём на следующем уроке (1.2), но прямо сейчас устроим быстрый тест-драйв: создадим таблицу games, положим 4 игры и зададим базе пару вопросов!

SQL · Создаём таблицу games и кладём 4 игры 
CREATE TABLE games (
    id           INT,
    title        TEXT,
    release_year INT,
    rating       NUMERIC
);

INSERT INTO games (id, title, release_year, rating) VALUES
    (1, 'Minecraft', 2011, 9.5),
    (2, 'Terraria',  2011, 9.3),
    (3, 'Portal 2',  2011, 9.8),
    (4, 'Hades',     2020, 9.4);

-- Ищем хиты с рейтингом 9.5 и выше, сортируя от лучшего к худшему
SELECT title, release_year, rating
FROM games
WHERE rating >= 9.5
ORDER BY rating DESC;
Ответ PostgreSQL
   title   | release_year | rating
-----------+--------------+--------
 Portal 2  |         2011 |    9.8
 Minecraft |         2011 |    9.5
(2 rows)

Посмотри таблицу мета-командами \dt и \d games, а когда наиграешься — убери её за собой командой DROP TABLE games;.

В дополнение к psql удобно использовать встроенный веб-клиент Adminer (docker compose --profile ui up -d → http://localhost:8080) или поставить бесплатный DBeaver Community / DataGrip. Параметры подключения к контейнеру с компьютера: Host localhost, Port 5432, Database learning_db, User student, Password student_pass.

06 Мини-практикум для закрепления

Выполни эти 4 задания самостоятельно в своей базе learning_db (внутри psql), прежде чем открывать эталонное решение.

Задание 1. Калькулятор времени

Напиши один SELECT-запрос, который посчитает: 1) сколько секунд в одних сутках (24 * 60 * 60), 2) какая дата наступит ровно через 100 дней от сегодня. Дай колонкам понятные английские имена через AS.

Показать решение
SQL 
SELECT
    24 * 60 * 60       AS seconds_in_day,
    current_date + 100 AS date_in_100_days;
Задание 2. Экскурсия по кластеру

Внутри psql включи секундомер выполнения запросов, выведи список всех баз данных вместе с их размерами на диске, перейди в системную базу postgres, а затем вернись обратно в learning_db.

Показать решение
SQL 
\timing
\l+
\c postgres
\c learning_db
Задание 3. Свой мини-каталог фильмов

Создай таблицу movies с колонками id (INT), title (TEXT) и score (NUMERIC). Добавь туда 3 своих любимых фильма и выведи их, отсортировав от самой высокой оценки к самой низкой.

Показать решение
SQL 
CREATE TABLE movies (
    id    INT,
    title TEXT,
    score NUMERIC
);

INSERT INTO movies (id, title, score) VALUES
    (1, 'Интерстеллар', 8.7),
    (2, 'Человек-паук', 8.4),
    (3, 'Начало',       8.8);

SELECT *
FROM movies
ORDER BY score DESC;
Задание 4. Краш-тест «флешки с сохранениями»

Не удаляя таблицу movies, выйди из psql (\q). Полностью пересоздай контейнер через docker compose down и docker compose up -d. Снова проверь SELECT * FROM movies; — убедись, что фильмы пережили пересоздание контейнера благодаря volume!

Показать решение
BASH 
# 1. Пересоздаём контейнер (БЕЗ флага -v!)
docker compose down
docker compose up -d

# 2. Проверяем, что таблица movies на месте
docker exec -it course_pg_primary psql -U student -d learning_db -c "SELECT * FROM movies;"
