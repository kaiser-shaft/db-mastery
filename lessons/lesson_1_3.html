Главное в этом уроке

01 Подготовка данных и первый разговор с базой через SELECT

В прошлом уроке мы научились создавать таблицы и заполнять их данными. Но база, в которую только складывают строки и ничего не читают — как школьная библиотека, куда библиотекарь сносит книги, но никому их не выдаёт. Сегодня ты станешь тем самым читателем, который умеет за секунду достать с нужной полки ровно ту книгу, которая нужна.

Представь витрину интернет-магазина мерча для программистов. У каждого товара есть название, категория, цена, скидка, остаток на складе и рейтинг покупателей. Чтобы все примеры из этого урока гарантированно заработали у тебя в learning_db, сначала запусти этот блок подготовки таблицы products.

SQL · Подготовка таблицы products в learning_db 
-- Пересоздаём таблицу товаров, чтобы у всех были одинаковые стартовые данные
DROP TABLE IF EXISTS products;

CREATE TABLE products (
  id           INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  title        TEXT NOT NULL,
  category     TEXT NOT NULL,
  price        NUMERIC(10, 2) NOT NULL CHECK (price > 0),
  discount_pct INT CHECK (discount_pct BETWEEN 0 AND 90), -- NULL = скидка не задана
  stock        INT NOT NULL DEFAULT 0 CHECK (stock >= 0),
  rating       NUMERIC(2, 1) CHECK (rating BETWEEN 1.0 AND 5.0) -- NULL = отзывов ещё нет
);

Теперь давай зададим базе первый вопрос. Команда SELECT (в переводе «выбрать») — это твой заказ официанту: ты перечисляешь, какие именно колонки хочешь увидеть, а в FROM указываешь, из какой таблицы их нести. Более того, прямо внутри SELECT можно считать простые формулы и давать колонкам красивые временные имена — псевдонимы (aliases) через слово AS.

SQL · Пример 1: выбор колонок, вычисления и псевдонимы 
-- Берём только нужные колонки и сразу считаем цену за 2 штуки
SELECT
  title AS product_name,
  price,
  price * 2 AS price_for_two
FROM products;

Как убрать повторы: DISTINCT

Допустим, дизайнер рисует боковое меню каталога и спрашивает: «А какие вообще категории товаров у нас есть?». Если просто написать SELECT category FROM products, база честно вернёт 10 строк, где «Одежда» и «Аксессуары» повторятся по 3 раза. Чтобы схлопнуть дубликаты в чистый список уникальных значений, добавь слово DISTINCT сразу после SELECT.

SQL · Пример 2: список уникальных категорий 
-- Оставляем только уникальные названия категорий
SELECT DISTINCT category
FROM products;
Ответ PostgreSQL
  category
------------
 Гаджеты
 Одежда
 Аксессуары
 Книги
(4 rows)
Совет на будущее: Запись SELECT * («принеси все колонки») удобна, чтобы быстро заглянуть в таблицу в терминале psql. Но в реальном коде сайта или приложения всегда перечисляй нужные колонки явно — это экономит трафик, ускоряет запросы и не ломает программу, если завтра в таблицу добавят новую тяжёлую колонку вроде description.

02 Фильтрация строк: WHERE и скрытый порядок выполнения

Когда ты заходишь на маркетплейс, ты почти никогда не листаешь все миллион товаров подряд. Ты ставишь галочки в фильтрах: «в наличии», «цена от 2000 до 10 000», «категория Одежда или Книги». В SQL эту роль играет блок WHERE (пропускной пункт для строк): каждая строка таблицы проверяется на условие, и дальше проходят только те, для которых условие оказалось истинным (TRUE).

Оператор Что делает (на человеческом) Пример в WHERE
=, <> (или !=) Равно / не равно category = 'Книги'
>, <, >=, <= Больше, меньше, не меньше, не больше stock > 0
BETWEEN a AND b Попадает в отрезок включая границы a и b price BETWEEN 2000 AND 10000
IN (...) Совпадает с любым значением из списка category IN ('Одежда', 'Книги')
LIKE / ILIKE Поиск по шаблону (% — любые символы, _ — 1 символ). ILIKE в PostgreSQL не различает регистр букв! title ILIKE '%postgres%'
AND, OR, NOT Логические «И», «ИЛИ», «НЕ» для связки условий stock > 0 AND price < 5000

Давай соберём живой поисковый запрос: найдём товары в наличии, которые либо относятся к одежде/книгам и стоят от 2000 до 10 000, либо содержат в названии слово postgres (в любом регистре).

SQL · Пример 3: комбинированная фильтрация с IN, BETWEEN и ILIKE 
-- Скобки гарантируют, что проверка stock > 0 сработает для обеих веток OR
SELECT id, title, category, price, stock
FROM products
WHERE stock > 0
  AND (
    (category IN ('Одежда', 'Книги') AND price BETWEEN 2000 AND 10000)
    OR title ILIKE '%postgres%'
  );
Ответ PostgreSQL
 id |         title         |  category  |  price  | stock
----+-----------------------+------------+---------+-------
  2 | Футболка «SELECT *»   | Одежда     | 5900.00 |    25
  3 | Стикерпак «Postgres»  | Аксессуары | 1200.00 |   100
  5 | Книга «SQL за 7 дней» | Книги      | 4200.00 |    14
  8 | Кепка «NULL Safety»   | Одежда     | 3900.00 |    19
 10 | Блокнот архитектора   | Книги      | 2100.00 |    30
(5 rows)
✗ Как НЕ надо
SELECT title, category, stock
FROM products
WHERE stock > 0
  AND category = 'Одежда'
   OR category = 'Аксессуары';

У AND приоритет выше, чем у OR (как у умножения перед сложением!). В результат просочится «Коврик для мыши XL» с stock = 0, потому что условие OR category = 'Аксессуары' сработает без проверки остатка.

✓ Как правильно
SELECT title, category, stock
FROM products
WHERE stock > 0
  AND (category = 'Одежда'
    OR category = 'Аксессуары');

Всегда ставь скобки, когда смешиваешь AND и OR (или заменяй цепочку OR на аккуратный category IN ('Одежда', 'Аксессуары')).

Почему WHERE «не видит» псевдонимы из SELECT?

Вот здесь спотыкается каждый второй новичок. Мы пишем запрос сверху вниз: сначала SELECT, потом FROM, потом WHERE. Кажется логичным придумать псевдоним promo_price в SELECT и сразу отфильтровать по нему в WHERE. Попробуем запустить такой запрос!

SQL · Попытка использовать псевдоним из SELECT внутри WHERE 
SELECT
  title,
  price * 0.9 AS promo_price
FROM products
WHERE promo_price < 5000;
Ошибка PostgreSQL
ERROR:  column "promo_price" does not exist
LINE 5: WHERE promo_price < 5000;
              ^

Почему база ругается, что колонки promo_price не существует, хотя мы сами объявили её тремя строчками выше? Дело в том, что порядок записи SQL и реальный порядок его выполнения внутри PostgreSQL не совпадают. Представь конвейер на заводе: сначала рабочие достают коробки со склада (FROM), потом отбраковывают неподходящие (WHERE), и только после этого клеят красивые этикетки на оставшиеся товары (SELECT).

Запомни простое правило: В WHERE нужно повторять саму формулу (WHERE price * 0.9 < 5000), потому что псевдонимов из SELECT на этом шаге ещё нет. А вот в ORDER BY псевдоним promo_price использовать уже можно — сортировка идёт позже!

03 Сортировка (ORDER BY) и пагинация (LIMIT / OFFSET)

Важнейшее правило реляционных баз данных, о котором часто забывают: таблица — это мешок со строками, а не пронумерованный список. Если ты не указал ORDER BY, PostgreSQL имеет полное право возвращать строки в любом удобном ему порядке (сегодня в одном, а завтра после обновления записи — в другом).

Чтобы навести порядок, как в таблице лидеров любимой игры, используется ORDER BY. Направление задаётся словами ASC (по возрастанию — от меньшего к большему, стоит по умолчанию) и DESC (по убыванию — от большего к меньшему). Можно указывать сразу несколько критериев через запятую: если по первому полю вышла ничья, база сравнит строки по второму!

Скрытая особенность PostgreSQL: куда деваются NULL при сортировке?

В PostgreSQL при сортировке по убыванию (DESC) пустые значения NULL считаются «самыми большими» и внезапно вылезают на самую вершину списка! Представь, что ты сортируешь товары «сначала с лучшим рейтингом», а на первом месте оказываются новинки вообще без оценок. Чтобы отправить пустоту в подвал, в PostgreSQL есть элегантная команда NULLS LAST (или наоборот — NULLS FIRST).

SQL · Пример 4: многоуровневая сортировка с NULLS LAST 
-- Сначала лучший рейтинг (без рейтинга — в конец),
-- при равном рейтинге — кто дешевле, а на крайний случай — по id
SELECT id, title, rating, price
FROM products
ORDER BY rating DESC NULLS LAST, price ASC, id ASC;
Ответ PostgreSQL
 id |         title         | rating |  price
----+-----------------------+--------+----------
  5 | Книга «SQL за 7 дней» |    4.9 |  4200.00
  1 | Худи «SQL Master»     |    4.9 | 14500.00
  7 | Клавиатура «MechPro»  |    4.9 | 18900.00
  3 | Стикерпак «Postgres»  |    4.8 |  1200.00
  2 | Футболка «SELECT *»   |    4.7 |  5900.00
  4 | Термокружка кодера    |    4.6 |  6900.00
  9 | USB-хаб «Docker Port» |    4.5 |  7400.00
  6 | Коврик для мыши XL    |    4.4 |  3500.00
 10 | Блокнот архитектора   |        |  2100.00
  8 | Кепка «NULL Safety»   |        |  3900.00
(10 rows)

Обрати внимание на две нижние строки в колонке rating: по умолчанию терминал psql рисует NULL как обычную пустоту! Чтобы всегда отличать NULL от пустой строки, можешь ввести в psql удобную мета-команду \pset null 'NULL' — тогда на месте пустых ячеек будет чётко печататься слово NULL.

Пагинация: как нарезать каталог на страницы

Когда в магазине 50 000 товаров, сайт никогда не загружает их разом — браузер бы просто завис. Вместо этого каталог делят на страницы, например по 3 или по 20 карточек. В SQL это называется пагинацией (pagination), и за неё отвечают два слова:

  • LIMIT N — сколько максимум строк отдать на этой странице;
  • OFFSET K — сколько первых строк пропустить от начала списка.
SQL · Пример 5: получаем 2-ю страницу каталога (по 3 товара на странице) 
-- Стр. 1: LIMIT 3 OFFSET 0
-- Стр. 2: LIMIT 3 OFFSET 3
SELECT id, title, price
FROM products
ORDER BY price ASC, id ASC
LIMIT 3 OFFSET 3;
Ответ PostgreSQL
 id |         title         |  price
----+-----------------------+---------
  8 | Кепка «NULL Safety»   | 3900.00
  5 | Книга «SQL за 7 дней» | 4200.00
  2 | Футболка «SELECT *»   | 5900.00
(3 rows)
✗ Как НЕ надо
SELECT id, title, price
FROM products
LIMIT 3 OFFSET 3;

Пагинация без ORDER BY — лотерея! Пользователь перейдёт на 2-ю страницу и увидит товар, который уже видел на 1-й, а какой-то другой товар вообще пропадёт.

✓ Как правильно
SELECT id, title, price
FROM products
ORDER BY price ASC, id ASC
LIMIT 3 OFFSET 3;

Жёсткая сортировка плюс уникальный «разбиватель ничьих» id ASC в конце гарантируют, что порядок страниц всегда будет стабильным.

Частая ошибка на больших проектах: Не используй огромный OFFSET (например, LIMIT 20 OFFSET 500000) на таблицах с миллионами строк. Чтобы пропустить 500 000 строк, PostgreSQL всё равно придётся честно прочитать их, отсортировать и выкинуть в корзину. В высоконагруженных системах для глубоких страниц применяют курсорную пагинацию (WHERE id > last_seen_id LIMIT 20) — мы ещё вернёмся к этому трюку в теме индексов!

04 Коварство NULL: почему «неизвестно» ломает привычную логику

Представь три коробки со скидочными купонами:

  • В первой коробке лежит бумажка с числом 10 (скидка 10%).
  • Во второй коробке лежит бумажка с числом 0 (скидки точно нет, она равна нулю).
  • А третья коробка вообще закрыта замком с вопросительным знаком — мы не знаем, что внутри. Вот это и есть NULL.

NULL — это не ноль и не пустая строка ''. Это маркер отсутствия данных («неизвестно»). И из-за этого в SQL вместо привычной логики «Истина / Ложь» действует трёхзначная логика (Three-Valued Logic): любое обычное сравнение с NULL (NULL = NULL, NULL <> 10, NULL < 15) возвращает не TRUE и не FALSE, а третье состояние — UNKNOWN («неизвестно»).

Из-за этого возникает одна из самых коварных ошибок в SQL: если написать WHERE discount_pct <> 10 («покажи все товары, у которых скидка НЕ 10%»), ты потеряешь все 4 товара, где скидка равна NULL! Чтобы работать с пустотой честно, используй специальные операторы:

  • IS NULL / IS NOT NULL — проверка, пуста ли ячейка;
  • IS DISTINCT FROM — «безопасное не равно», которое считает, что NULL отличается от 10 (вернёт TRUE!).
✗ Как НЕ надо
-- 1) Всегда вернёт 0 строк!
SELECT * FROM products
WHERE discount_pct = NULL;

-- 2) Потеряет товары с NULL!
SELECT * FROM products
WHERE discount_pct <> 10;

Операторы = и <> при встрече с NULL выдают UNKNOWN, и WHERE безжалостно выкидывает эти строки.

✓ Как правильно
-- 1) Находим товары без скидки
SELECT * FROM products
WHERE discount_pct IS NULL;

-- 2) Не 10%, включая NULL!
SELECT * FROM products
WHERE discount_pct IS DISTINCT FROM 10;

Операторы IS NULL и IS DISTINCT FROM возвращают строго TRUE или FALSE — никаких сюрпризов.

SQL · Пример 6: ищем товары, у которых ещё нет оценки (IS NULL) 
-- Находим новинки без рейтинга, которые есть в наличии
SELECT id, title, price, rating
FROM products
WHERE rating IS NULL
  AND stock > 0
ORDER BY id ASC;
Ответ PostgreSQL
 id |        title        |  price  | rating
----+---------------------+---------+--------
  8 | Кепка «NULL Safety» | 3900.00 |
 10 | Блокнот архитектора | 2100.00 |
(2 rows)

NULL-вирус в формулах и лекарство COALESCE

У NULL есть ещё одно «суперзлодейское» свойство: в любой арифметической формуле он заражает весь результат. Сколько будет 1200 - неизвестно? Правильно — неизвестно (NULL)! Если ты просто посчитаешь цену со скидкой для стикерпака, у которого discount_pct IS NULL, его итоговая цена исчезнет и превратится в NULL.

Спасает встроенная функция COALESCE(a, b, ...) — представь её как запасного вратаря. Она просматривает аргументы слева направо и возвращает первое не-NULL значение. Запись COALESCE(discount_pct, 0) читается просто: «возьми скидку из колонки, а если там NULL — подставь ноль».

SQL · Пример 7: сравнение сломанной формулы и безопасного COALESCE 
-- Посмотрим на гаджеты и аксессуары: что случится без COALESCE и с ним
SELECT
  title,
  price,
  discount_pct,
  ROUND(price * (100 - discount_pct) / 100.0, 2) AS broken_price,
  ROUND(price * (100 - COALESCE(discount_pct, 0)) / 100.0, 2) AS final_price
FROM products
WHERE category IN ('Гаджеты', 'Аксессуары')
ORDER BY id ASC;
Ответ PostgreSQL
         title         |  price   | discount_pct | broken_price | final_price
-----------------------+----------+--------------+--------------+-------------
 Стикерпак «Postgres»  |  1200.00 |              |              |     1200.00
 Термокружка кодера    |  6900.00 |           15 |      5865.00 |     5865.00
 Коврик для мыши XL    |  3500.00 |            5 |      3325.00 |     3325.00
 Клавиатура «MechPro»  | 18900.00 |           20 |     15120.00 |    15120.00
 USB-хаб «Docker Port» |  7400.00 |            0 |      7400.00 |     7400.00
(5 rows)
Осторожно с NOT IN и NULL! Если внутри списка NOT IN (10, 20, NULL) окажется хотя бы один NULL, весь запрос вернёт ровно 0 строк. Почему? Потому что x NOT IN (10, NULL) раскрывается как x <> 10 AND x <> NULL, а вторая часть всегда даёт UNKNOWN. Всегда проверяй, могут ли в списке оказаться пустые значения!

05 Мини-практикум для закрепления

Выполни все 4 задания в своей базе learning_db (таблица products из раздела 01), прежде чем открывать эталонные решения. Старайся сначала проверить результат глазами, а потом свериться со спойлером.

Задание 1 (Базовое). Бюджетный каталог одежды и книг

Выведи колонки title, category и price для всех товаров из категорий 'Одежда' и 'Книги', которые стоят строго меньше 6000. Отсортируй результат от самого дешёвого товара к самому дорогому.

Показать решение
SQL 
SELECT title, category, price
FROM products
WHERE category IN ('Одежда', 'Книги')
  AND price < 6000
ORDER BY price ASC, id ASC;
Задание 2 (Поиск по тексту). Фанаты SQL и Postgres

Найди все товары, у которых в названии (title) встречается слово sql или слово postgres — без учёта регистра букв. Покажи их id, title и остаток stock, отсортировав по id.

Показать решение
SQL 
SELECT id, title, stock
FROM products
WHERE title ILIKE '%sql%'
   OR title ILIKE '%postgres%'
ORDER BY id ASC;
Задание 3 (Пагинация и NULLS LAST). Вторая страница витрины

Получи 2-ю страницу каталога (размер страницы — 3 товара). Товары должны быть отсортированы от самого высокого рейтинга к самому низкому так, чтобы новинки без рейтинга (NULL) оказались в самом конце. При одинаковом рейтинге выше должен идти более дешёвый товар, а на случай полного совпадения — с меньшим id.

Показать решение
SQL 
-- Пропускаем 1-ю страницу (3 товара) и берём следующие 3
SELECT id, title, rating, price
FROM products
ORDER BY rating DESC NULLS LAST, price ASC, id ASC
LIMIT 3 OFFSET 3;
Задание 4 (Со звёздочкой). Безопасная арифметика и коварный NULL

Выведи товары, которые есть в наличии (stock > 0) и у которых скидка либо не задана (NULL), либо меньше 15 процентов. В результате покажи title, исходную price, скидку под именем discount (если NULL — выводи 0) и итоговую цену со скидкой final_price (округлённую до 2 знаков). Отсортируй результат от самой низкой final_price к самой высокой.

Показать решение
SQL 
-- Обрати внимание: в ORDER BY псевдоним final_price работает,
-- потому что сортировка выполняется ПОСЛЕ шага SELECT!
SELECT
  title,
  price,
  COALESCE(discount_pct, 0) AS discount,
  ROUND(price * (100 - COALESCE(discount_pct, 0)) / 100.0, 2) AS final_price
FROM products
WHERE stock > 0
  AND (discount_pct IS NULL OR discount_pct < 15)
ORDER BY final_price ASC, id ASC;
